# BioLab — дизайн-документ (черновик v0.2)

> Рабочее название: **BioLab**, id мода `biolab`. Платформа: [Horizon](https://github.com/horizon-rust/horizon) — Minecraft Java 26.3, переписанный на Rust.
> Дата: 2026-10-31. Статус: черновик, до начала кода.

---

## 1. Идея в одном абзаце

Био-химическая лаборатория в Minecraft. Игрок собирает образцы из мира (мобы, почва, гниль, растения), выращивает культуры, синтезирует вещества в реакторах, делает из них лекарства и яды, а в эндгейме редактирует гены растений и микробов и клонирует мобов. Мир даёт угрозы — **болезни** — и лаборатория становится не декорацией, а способом выжить.

**Главная петля:** *найти угрозу или ресурс → взять образец → исследовать → синтезировать → применить (вылечить / усилить / автоматизировать) → открыть следующий уровень.*

## 2. Столпы дизайна

1. **Наука, но игровая.** Реальные идеи (агар из водорослей, пенициллин из плесени, электролиз соли, период полувыведения), упрощённые до понятных механик. Никаких таблиц Менделеева на 118 клеток.
2. **Всё связано.** Микробиология даёт сырьё для химии, химия — лекарства, лекарства лечат болезни из микробиологии, генетика улучшает всё остальное.
3. **Риск в лаборатории.** Реакции греются, газы травят, культуры заражают. Защитный костюм и вытяжка нужны по делу.
4. **Открытие, а не рецепт из вики.** Неизвестное вещество нужно сначала проанализировать. Лабораторный журнал заполняется по мере открытий.

## 3. Платформа: что можно и какой ценой

Источник: исходники horizon (коммит `d6e8bd6`, 2026-10-31), `docs/mods.md`, `docs/native-mods.md`, horizon-mixins, playhorizon.dev/docs/make-a-mod. Пути вида `mobs.rs:2405` — внутри `crates/horizon-client/src/`.

### 3.1 Два уровня доступа

Нативный мод — это **миксины**: перед компиляцией код мода встраивается в исходники игры (HEAD, RETURN, OVERWRITE, MODIFY_*, `[[state]]` — новое поле в структуре игры). Цепляться можно к двум видам целей:

| | Hook points (`native_*`, API 45) | Внутренние функции игры |
|---|---|---|
| Что даёт | Машины, слоты, экраны, тик игрока, random tick, свои типы рецептов, спавн мобов, команды, HUD, сеть | Всё остальное: тики эффектов, атрибуты, AI мобов, их сохранение, рендер, дроп, жидкости |
| Обновления | Мод собирается на новых Nightly без правок | Мод **пиннится** на коммит (`horizon_revision`), после каждого обновления хуки надо перепроверять |
| Риск | Низкий | Средний–высокий: функцию переименуют — сборка падает |

**Решение:** логику делим на два нативных мода.
- `biolab-core` — только hook points. Машины, химия, болезни, фармакология, генетика растений. Живёт долго и не ломается.
- `biolab-deep` — миксины на внутренности. Поведение эффектов, мутанты, внешний вид, кислота. Пиннится на коммит и обновляется вручную. Компилируется в тот же крейт игры, поэтому видит модуль `core`. Без `deep` мод играбелен, но беднее.

### 3.3 Эффекты

- Эффекты — это **таблица со строковыми id**, не enum (`horizon-client-core/src/potions.rs:15-126`). Эффект контентного мода `biolab:x` уже работает как полноценный: сохраняется, уходит по сети, принимается `/effect`. Не хватает только поведения.
- Поведение ванильных эффектов захардкожено в `match` по строкам, поэтому своё добавляем хуками:
  - **у игроков** (хост и все гости): HEAD/RETURN на `game::potions::Game::tick_mob_effects` (`game/potions.rs:754`);
  - **у мобов**: HEAD на `mobs::ai::tick_effects` (`mobs/ai.rs:2424`);
  - **модификаторы атрибутов**: RETURN на `PlayerEffects::modifiers` (`horizon-client-render/src/effects.rs:372`) у игрока, `Mob::movement_speed` у моба;
  - **наложить эффект из кода**: `Game::add_player_effect` (`game/potions.rs:828`), `Mob::add_effect` (`mobs.rs:2926`). Снять — `retain` по списку.
- **Иконки — решено (2026-10-31).** Движок рисует иконку спрайтом `mob_effect/<id>`, то есть ищет ключ `mob_effect/biolab:acid_burn`, а из модов в атлас попадают только `textures/gui/...` под ключом `biolab:gui/mob_effect/acid_burn` — порядок частей другой, поиск промахивается. Чиним данными, а не отрисовкой: PNG кладём в `assets/biolab/textures/gui/mob_effect/`, а после сборки атласа добавляем псевдоним с нужным ключом (модуль `biolab_icons` в `horizon-client-render`). Одна правка — иконки появляются и в HUD, и в инвентаре, и работает это для любого мода.
  - Хук: `MODIFY_EXPRESSION_VALUE` на тело `HudAtlas::build_over` (`horizon-client-render/src/hud.rs`). `RETURN` там не встаёт: функция объявлена как `-> Result<Self>`, а инструменту нужен конкретный тип.
  - Подтверждено: миксины **умеют целиться в другие крейты**, не только в `horizon_client` (открытый вопрос 3 закрыт).
- **Ограничения:**
  - у игроков и мобов две разные модели эффектов, нужны два набора хуков;
  - колбэка «эффект снят» нет — сравниваем список до и после;
  - модификаторы считаются и на клиенте, поэтому клиенту тоже нужен мод.

### 3.4 Мобы

- Виды мобов — закрытый `enum Species` (`mobs/species.rs:7`, ~3200 веток в коде). **Новый вид не добавить**, зато **каждый экземпляр гибко меняется**:
  - **статы**: 9 атрибутов (здоровье, скорость, урон, броня, отбрасывание…) через `set_base` / `add_modifier` (`mobs/finalize.rs:594,617`);
  - **AI открытый**: `trait Goal` (`mobs/goals.rs:24`). Свои цели (плеваться кислотой, бояться света, охотиться на животных) добавляются в `m.ai.goals`;
  - **момент рождения**: RETURN на `mobs::spawning::finalize` (`spawning.rs:166`) или HEAD на `Game::native_mobs_joined` — тут бросаем мутацию;
  - **дроп**: RETURN на `drops::die` (`mobs/drops.rs:401`) дописывает свои предметы;
  - **внешний вид**: RETURN на `mobs::render::body` (текстура, `render.rs:199`), `body_color` (тинт), `layers` (оверлеи), `species_scale` (визуальный размер). Так уже сделаны Toast, jeb_ и Dinnerbone. PNG кладутся в `minecraft/textures/entity/biolab/…`. Хитбокс отдельно, через `Mob::bounds_at`.
- **Сохранение генома.**
  - Horizon **сохраняет неизвестные NBT-ключи** (`game/persist.rs:25-33`, `entity_nbt.rs:325`). Ключ `biolab:genome` переживёт перезагрузку.
  - Запись: RETURN на `entity_nbt::mob_to_nbt`.
  - Чтение: лениво из `persist.raw` (на функции загрузки с `?` RETURN не встаёт). После загрузки статы и цели применяем заново.
- **Сеть:** клиент видит мутанта обычным ванильным мобом. Внешний вид мутанта видят только клиенты с модом: сервер отправляет его через mod-net (API 40).

### 3.5 Жидкости

- **Настоящая жидкость невозможна.** Вода и лава зашиты в enum, в рендер (`mesher/fluid.rs:224-312`), физику, вёдра и растекание (`horizon-world/src/level/fluids.rs`). Блок мода с шаблоном `minecraft:water` получается сломанным: невидимым и разливающим обычную воду.
- **v1 — псевдожидкость** (hook points, переживает обновления):
  - блок с уровнями 1–8 (шаблон вроде `snow` с пустой коллизией), своя полупрозрачная текстура;
  - растекается нашими запланированными тиками, ограниченно: лужа, а не океан. Испаряется;
  - ставится из своего ведра (`native_use_item_on`);
  - эффекты на игрока через `native_player_tick`, на мобов через миксин;
  - **нет** плавания, течения и подводного тумана.
- **Сделано (2026-11-01). Лужи действуют и на мобов: моб, стоящий в луже, получает её эффект из общего тика поведения.** v1 (2026-11-01):** три лужи — кислота, шлам, слизь — блоками со слоями по шаблону снега. Разливаются ведром, действуют на стоящего в них (эффект плюс заражение у слизи) и подсыхают на слой за срабатывание. Ведутся из тика игрока, без тиков блоков: тиковые хуки живут на уровне, а имя блока по состоянию там не достать. Поэтому лужи не текут и не действуют на мобов.
- **v2 — «вода с другим именем»** (опционально, `deep`, ~10 миксинов):
  - настоящая плавающая кислота со своим цветом и текстурой;
  - но в ванильных местах она ведёт себя как вода: тушит огонь, увлажняет грядки, впитывается губкой. Каждое такое место нужно ловить отдельно;
  - **высокий риск, отложено.**


### 3.6 Что выяснилось при постройке машин (2026-11-01)

- **Меню машины можно не рисовать.** `ModContainer` умеет открыть ванильное меню печки: три слота и четыре числа данных, из которых клиент сам рисует пламя и шкалу. Заголовок берётся из названия блока. Своя отрисовка (API 19–20) нужна будет только машинам со сложным экраном — синтезатору, секвенатору.
- **Помощники рецептов API 36 на сервере не работают.** `native_recipes_of_type`, `native_recipe_ingredient` и `native_recipe_result` начинаются с проверки `self.player`, которого в серверном `Game` нет, и всегда отдают пусто — а машины тикают именно там. Обход: читать `game.recipes().custom` и разбирать через `crafting::Ingredient::parse` и `crafting::recipe_result`. Это внутренний API. **Сообщить разработчикам Horizon.**
- **Команда `item replace block` не видит контейнер мода**, поэтому в прогонах машины заряжаются воронкой сверху, а содержимое читается через `data get block`.
- **Правый клик рядом с машиной достаётся блоку**, а не предмету в руке: для проверки `native_use_item` нужно отойти и смотреть в небо.
- **Серверные команды модов в одиночной игре не работают.** `native_register_commands` вызывается, но команды ставит только хост сети (`register_native_commands` требует `LanHost`), поэтому в одиночной игре даже зарегистрированная команда отвечает «неизвестная». Команды мода живут на клиенте (`native_command`).
- **Запрос клиент → сервер не доходит в одиночной игре**: `native_net_send_to_server` молчит, обратное направление (`native_net_send_to_player`) работает. Поэтому данные для панелей сервер шлёт сам, а не по запросу.
- **У клиентской стороны нет корня мира.** HUD живёт на клиенте, а состояние игрока — на сервере, и читать файл мира с клиента нельзя: поле `world_root` там пустое. Данные для панелей идут сообщением сервер → клиент (API 40, `native_net_send_to_player`). Это же понадобится всем будущим HUD мода.

### 3.7 Что выяснилось при фармакологии (2026-11-01)

- **Длительность эффекта — плохие часы.** Поведение своих эффектов считалось по остатку `duration` (`duration % период == 0`). Пока эффект ставился один раз, это работало, но фармакология подновляет свои эффекты каждую секунду, остаток всё время прыгает к 60 и через кратное период число просто не проходит: токсикоз висел на игроке и не бил ни разу. Теперь ритм отсчитывают часы самой игры (`game.ticks` у игрока, `m.age` у моба).
- **`tick_mob_effects` вызывается чаще раза в тик** (ещё и из `lan_actions`), поэтому собственный счётчик вызовов тоже не годится: с ним токсикоз бил впятеро чаще расчётного и убивал за пять секунд.
- **Один клик достаётся двум хукам.** `native_interact_entity` с `claimed` всё равно пропускает `native_use_item`: шприц яда доставался и корове, и игроку. Обход — запоминать тик инъекции и пропускать приём, если он пришёл сразу следом.
- **`native_give` из хуков предмета доходит не всегда**: пустой шприц от вакцины пропадал совсем. Надёжнее подменять опустевший стак прямо в слоте через `native_carried_stack`.
- **Плоский мир для проверок лучше обычного**, но слаймы в нём спавнятся пачками и мешают мерить урон: для опытов — площадка на `y=21` и `kill @e[type=minecraft:slime]`.

### 3.8 Что выяснилось в генетике (2026-11-01)

- **`native_give` работает только в творческом режиме** (`recipe_give` проверяет `self.creative`): в выживании мутантная ткань просто пропадала. Предметы мода кладём прямо в свободный слот через `native_carried_slot`.
- **Создать предметную сущность хуки не умеют**: `native_item_entities` и `native_set_item_entity` только читают и меняют уже выпавшие. Поэтому «дроп» с мутанта — это выдача в рюкзак убийце.
- **Клик по мобу снова достаётся обоим хукам** (`native_interact_entity` и `native_use_item`), теперь это общая отметка `remember_injection` для шприцев, микроскопа и фрагментов ДНК.
- **Эффекты мода принимают только `category` и `color`** — модификаторов атрибутов в них нет, поэтому генотерапия игрока держится на ванильных эффектах, а не на своих.
- **`native_level_tick_post` в одиночной игре не вызывается** — ровно как серверные команды модов. Поведение мутантов, которому нужны все мобы разом, висит на `native_player_tick`: туда можно подписать и вторую инъекцию, рядом с уже имеющейся.
- **Скорость моба бесполезно менять из хука:** ванильный тик моба перезапишет её своей, и подопытный уходил из вольера. Возвращает его `native_teleport_mob` (API 37).
- **Правый клик пустой рукой до `native_use_item_on` не доходит** — там обязателен предмет. Сбор урожая с грядки пришлось перенести в `native_right_click_block` (API 21), который ловит клик всегда.
- **Правый клик рядом с машиной снова съел проверку:** стоя вплотную к инкубатору, клик уходит в блок и `native_use_item` не вызывается вовсе. Проверять предметы — отойдя от машин.
- **Статы мутанта ставит lib-часть, а не бинарник.** Так ген, вживлённый уколом уже живому мобу, получает прибавки там же, где читаются метки, без перезахода в мир.

Элемент — предмет-порошок или газ в баллоне. Добываются разделением ванильных предметов (тир 1–2): дробилка, перегонный куб, электролизёр, выпариватель.

**Модель вещества.** Реестр `Compound`: id, название, формула, агрегатное состояние (твёрдое / жидкость / газ), цвет, опасности (токсичное, едкое, горючее, взрывоопасное), теги свойств (кислота, основание, растворитель, катализатор, сахар, белок…).

**Где хранятся.**
- Твёрдые — обычные предметы (порошки, кристаллы).
- Жидкости и газы — в **колбах** (стеклянная колба 250 мл, ампула, баллон для газа). Колба с веществом — отдельный предмет на вещество (MVP) либо одна колба с `custom_data` (если подтвердится запись компонентов).
- Внутри машин — баки в миллилитрах, показываются на экране машины.

**Реакция** = входы + условия → выходы + тепло.
```json
{ "type": "biolab:reactor",
  "inputs":   [{"compound": "biolab:sodium_chloride", "amount": 2}, {"compound": "biolab:water", "ml": 500}],
  "conditions": {"temperature": [20, 60], "power": "redstone", "catalyst": null},
  "outputs":  [{"compound": "biolab:chlorine", "ml": 250}, {"compound": "biolab:sodium_hydroxide", "amount": 2}],
  "heat": -5, "time": 200 }
```
- **Температура** машины — внутреннее число. Нагрев от соседних блоков (костёр, лава, магмовый блок) или своей горелки, охлаждение — лёд или холодильник. Экзотермические реакции разогревают реактор сами.
- **Перегрев** (> лимита) → утечка газа (частицы, отравление рядом) → взрыв на критической отметке. Вытяжка над реактором снижает риск.

**Диапазоны рецептов реактора — сделано (2026-11-01).** Нагрев ползёт к потолку источника и стоит на нём, а выход из диапазона сбрасывает прогресс, поэтому диапазон рецепта обязан накрывать потолок хотя бы одного источника (тест `every_reactor_recipe_has_a_steady_heat_source`). Ослабленная культура — 250–400 °C, на костре (300) или костре душ (350); прежние 60–140 °C не держал ни один источник, и культуру приходилось вымучивать огнивом. Бессмысленный «кальций → кислород» заменён обжигом кальцита: `minecraft:calcite` → кальций ×2, 400–900 °C (магма, огонь).

#### Формульный синтезатор: игрок собирает своё вещество

Главный механизм создания своего. На экране синтезатора игрок **набирает формулу**: слоты под элементы со счётчиками, плюс условия (температура, катализатор, давление). Мод не ищет готовый рецепт, а **считает результат из состава**.

**1. Проверка стабильности.** Сумма связей всех атомов должна быть чётной, и ни один атом не должен требовать больше связей, чем дают все остальные вместе. Иначе формула не собирается: смесь распадается на элементы, при высокой температуре — взрыв.

**2. Свойства выводятся из состава** (правила игровые, вдохновлены химией, но это не химия):

| Свойство | Как считается |
|---|---|
| Агрегатное состояние | По массе молекулы: лёгкая — газ, средняя — жидкость, тяжёлая — твёрдое |
| Цвет | Доминирующий красящий элемент: Cu голубой, Fe рыжий, I фиолетовый, S жёлтый, C чёрный, Gl светится |
| Горючесть | Есть C и H, кислорода меньше, чем углерода |
| Взрывоопасность | N вместе с избытком O (нитраты); растёт с Rs |
| Едкость | H + Cl/S без углерода (кислота) или Na/K + O + H (щёлочь) |
| Токсичность | Cl, избыток S, Fe/Cu внутри органики |
| **Биоактивность** | C ≥ 3, есть N и O. Сила растёт со сложностью молекулы |
| Питательность | Только C, H, O в пропорции сахаров |
| Растворимость | Отношение O к C |
| Катализ | Fe, Cu, Au, Rs без органики |

**3. Что получилось.**
- Формула совпала с **известным веществом** из таблицы мода (около 30 канонических: вода, соль, кислоты, спирты, глюкоза, пенициллин…) → каноническое имя, точные свойства, запись в журнал.
- Формула новая → **процедурное вещество**: свойства по правилам выше, имя сначала техническое (`C₇H₅NO₃ (неопознано)`), игрок даёт своё после испытаний.

**4. Биоактивное вещество — это препарат.** Из состава считаются параметры фармакологии (4.3): скорость всасывания, период полувыведения, терапевтическое окно, побочки. Так изобретённая молекула проходит путь до собственного лекарства — через испытания на подопытных (4.10).

Сырьё берётся из ванильных предметов (колонка «Откуда в игре» в таблице элементов): порох даёт селитру, серу и уголь, костная мука — фосфор и кальций, ламинария — йод и агар, соль с водой — хлор и щёлочь, гнилая плоть и паучий глаз — органику и токсины.

### 4.2 Микробиология

**Культура** — предмет «чашка Петри» со штаммом. У штамма есть вид (бактерия / плесень / дрожжи / вирус-фаг) и 3–5 генов-признаков: скорость роста, оптимальная температура, продукт, патогенность, устойчивость к антибиотикам.

**Источники штаммов** (мазок ватной палочкой):
- с мобов (клик по мобу, API 29): зомби → трупная бактерия, свинья → кишечная флора, мушрум → споры грибов;
- с блоков: почва/подзол → почвенные бактерии (стрептомицеты → антибиотики), гниющая еда → плесень, грибной блок → грибница;
- из воды болот → патогены.

**Инкубатор** (block entity): агар + мазок → культура растёт за N тиков при подходящей температуре. Неудачная температура → культура гибнет или мутирует (случайно меняется один ген).

**Ферментер:** культура + субстрат → продукт. Дрожжи + сахар → этанол + CO₂; уксуснокислые бактерии + этанол → уксус; пеницилл + питательная среда → пенициллин.

**Болезни игрока** (сервер, тик игрока API 31):
- Заражение: съесть гнилую плоть, удар зомби, пить из болотной воды, работа с патогенной культурой без перчаток, контакт с больным игроком рядом (мультиплеер).
- Стадии: инкубация (без симптомов) → симптомы (ванильные эффекты: голод, слабость, тошнота, медлительность) → кризис → выздоровление или смерть.
- Иммунитет после выздоровления или вакцины.
- **Устойчивость к антибиотикам:** недолеченная болезнь (курс прерван) мутирует в устойчивый штамм.

MVP-болезни: «трупная лихорадка» (от зомби и гнилой плоти, лечится пенициллином), «болотная лихорадка» (от болотной воды), «грибковая инфекция» (от мицелия и грибных коров).

### 4.3 Фармакология

**Препарат** = вещество + форма: таблетка (пресс), инъекция (шприц), мазь, аэрозоль. Форма влияет на скорость всасывания.

**Сделано (2026-11-01).** Семь веществ (пенициллин, обезболивающее, стимулятор, антидот, вакцина, седативное, яд), четыре формы и двенадцать готовых препаратов: таблетки с пресса, инъекции в шприцах, мазь, аэрозоли. Шприцем колют в упор, **дротиком** — по цели под прицелом за два десятка блоков: духовая трубка не нужна, цель выбирается по направлению взгляда.

**Кровотечение** замкнуто в цикл: зазубренный скальпель оставляет мобу кровоточащую рану, ген «рвущие когти» делает то же с игроком, а бинт перевязывает и немного лечит.

**Фармакокинетика на игроке** — мод хранит по каждому игроку концентрации веществ в крови:
- приём → концентрация растёт со скоростью всасывания;
- каждый тик убывает по **периоду полувыведения**;
- эффект действует, пока концентрация в **терапевтическом окне**;
- выше окна — **побочки и передозировка** (тошнота, урон, вплоть до смерти);
- частый приём → **толерантность** (окно сдвигается вверх).

**Анализатор крови** (предмет в руке) — HUD с концентрациями и активными болезнями (сервер шлёт данные клиенту, API 40).

Примеры препаратов MVP:

| Препарат | Откуда | Действие |
|---|---|---|
| Пенициллин | Плесень → ферментер → экстракция | Лечит бактериальные инфекции |
| Обезболивающее (салицилат) | Кора ивы ≈ листва берёзы → экстракт | Снимает слабость, при передозировке отравление |
| Стимулятор (кофеин) | Какао-бобы → экстракция | Скорость, спешка. Потом «откат» — усталость |
| Антидот | Активированный уголь | Снижает концентрацию всех веществ |
| Вакцина | Ослабленный штамм (нагрев культуры) | Иммунитет к болезни |
| Яд (для оружия) | Паучий глаз, иглобрюх → экстракт | Дротик или шприц на мобе (API 39) |

### 4.4 Генетика (эндгейм)

**Сделано (2026-11-01).** Восемь генов с ценой стабильности, геном мутанта из нескольких генов, мутантная ткань, экстрактор ДНК, фрагменты-предметы, сплайсинг уколом, микроскоп, клонирующий чан и генотерапия игрока. Следом закрыт и хвост этапа: мутаген, ГМ-грядка со скрещиванием и штаммы.

**ГМ-грядка.** Блок со слоями: слой — стадия роста. Геном растения живёт в блок-сущности строкой, как у мутанта. Сажают фрагментом ДНК или собранным урожаем, собирают правым кликом (этот хук ловит и пустую руку, в отличие от `native_use_item_on`). При созревании соседняя спелая грядка отдаёт свой лучший ген, если он влезает по стабильности, — это и есть скрещивание. Урожай несёт геном: съевший получает эффекты по генам, на время, без побочек генотерапии.

**Пул генов.** 31 ген: телосложение, внешность, обмен, железы и поведение. У каждого цена стабильности, и в организм влезает не больше трёх при сумме цен до шести — выбор гена всегда стоит отказа от другого. Поведение описано метками (`regen`, `acid_aura`, `predator`, `loyal`…), а не вшито в имена: новый ген с готовым поведением добавляется строкой таблицы.

**Что гены умеют.** Регенерация, негорючесть, стойкость к ядам, кислотная и холодная ауры, лечащая аура для соседей-мутантов, костяные шипы (ранят бьющего), ядовитая кровь (травит убийцу), лужа кислоты или заразная слизь после смерти, светобоязнь (днём мутант не охотится), хищник (сам выбирает жертвой мирную живность), стайность (прибавка, когда рядом свои) и лояльность (не трогает людей).

**Вольер и пульт.** Вольер держит подопытного: моб в его круге теряет цель, а ушедшего возвращает телепорт — гасить скорость бесполезно, ванильный тик моба перезаписывает её своей. Пульт рядом собирает отчёт: кто в вольерах, сколько у него здоровья, что в геноме, болен ли, и последние записи журнала испытаний — туда пишется каждая инъекция подопытному.

**Мутаген.** Эффект `biolab:mutagenesis` копит мутационную нагрузку: у мобов — в памяти бандла, у игрока — в состоянии мира. На пороге организм срывается, и в геном вписывается ген, который ещё влезает по стабильности; у игрока — только такой, что в человеке приживается. Мутаген вводят шприцем мобу или разливают лужей.


**Геном** — у растений и микробов: 4–6 генов с аллелями (доминантный / рецессивный).

- **Экстрактор ДНК:** образец (ткань моба, семена, культура) → «фрагмент ДНК» с одним геном.
- **Секвенатор:** показывает геном образца (экран со списком генов). До секвенирования образец — «неизвестный».
- **Сплайсер генов:** вставляет фрагмент в растение или микроб.
- **Скрещивание растений:** ГМ-грядка, соседние растения при random tick (API 33) дают потомство со смешанным геномом.

Гены, добытые из мобов (биология + фантазия):

| Источник | Ген | Растение или микроб получает |
|---|---|---|
| Светящийся спрут | Биолюминесценция | Светящиеся грядки, светящиеся культуры |
| Аксолотль | Регенерация | Растение отрастает после сбора |
| Страйдер | Термостойкость | Растёт в Незере, культура переносит жар |
| Паук | Шёлк | Бактерия-продуцент нити |
| Курица | Быстрый рост | Ускоренный цикл |
| Кактус | Засухоустойчивость | Растёт без воды |
| Крипер | Нестабильность | Плод взрывается при сборе (оружие или шутка) |

**Биовыщелачивание:** сконструированная бактерия в биореакторе превращает булыжник / гравий в крупицы металлов — биологическая альтернатива рудникам.

**Клонирование** (финал): полный геном моба + клонирующий чан + питательный раствор → спавн ванильного моба (API 37). С `biolab-deep` клон получает заданный игроком геном — мутации из 4.6.

### 4.5 Безопасность лаборатории

- **Средства защиты:** перчатки, очки, респиратор, костюм химзащиты (броня с компонентами). Без них — шанс отравления или заражения при работе.
- **Вытяжной шкаф:** снижает риск газа у соседних машин.
- **Заражённый блок:** разлив патогенной культуры → блок «заражён», источник болезни, пока не продезинфицируют (хлорка, этанол).

### 4.6 Мутации

Связывает генетику с миром: лаборатория не только лечит, но и **порождает угрозы**.

**Геном моба** (NBT `biolab:genome`): 4–6 генов из общего пула мутаций, у каждого сила 1–3.

| Мутация | Стат / AI | Вид |
|---|---|---|
| Гигантизм | +здоровье, +урон, −скорость | Визуально крупнее, хитбокс шире |
| Гиперметаболизм | +скорость, быстро голодает (теряет HP без еды) | Красноватый тинт |
| Хитиновый панцирь | +броня, +сопротивление отбрасыванию | Оверлей пластин |
| Кислотные железы | Новая цель AI: плевок кислотой (снаряд или псевдожидкость в точке попадания) | Зелёные пятна |
| Биолюминесценция | Светится, не горит на солнце | Светящийся оверлей |
| Светобоязнь | Убегает от факелов и света | Бледный |
| Хищник | Нападает на мирных животных | Тёмный тинт |
| Нестабильный геном | Мутирует дальше со временем, может взорваться при смерти | Мерцание |

**Естественные мутанты — сделано (2026-11-01).** Мутантом бывает любой живой моб, не только зомби: геном бросается при появлении моба в мире (`joined.rs` в deep), шанс — по нраву вида (`roll_for`, `runtime.rs` deep): враждебные — 15 %, нейтральные и мирные — 5 %. Никогда не мутируют боссы (дракон, иссушитель), древний страж и хранитель, жители, торговцы и лама торговца, големы (железный, снежный, медный), тихоня, броненосец, скрипун (его не убить без сердца), гигант и манекен — явная таблица `NEVER_MUTANT`; незнакомый вид не мутирует тоже. Мирным не выпадают гены, которым нужна атака: грубая сила, светобоязнь, хищник, лояльность, рвущие когти. Моб, загруженный с диска без меток, остаётся обычным — иначе каждый перезаход давал бы стаду новый бросок. Прибавка здоровья считается от базового здоровья вида (`scaled_stats`: от четверти до двойной зомбиной, срез — не больше половины базы), оттенок кладётся поверх ванильного цвета. Стая считает своими только мутантов своего вида, хищник-добыча не охотится. Заражение от близости к зомби — болезнь, а не мутация, и осталось за зомби.

**Источники мутаций:**
- **Мутаген** (химическое вещество, тир 2): эффект `biolab:mutagenesis` накапливает «мутационную нагрузку» на мобе. На пороге моб мутирует — RETURN на тик эффектов.
- **Заражённые зоны:** разливы псевдожидкостей, свалки культур. Мобы, рождённые рядом, получают мутации при спавне.
- **Клонирующий чан:** игрок задаёт геном сам — свои мутанты-защитники, ездовые, фермерские.
- **Утечка из лаборатории:** авария реактора с мутагеном мутирует мобов в радиусе.

**Что игрок получает:**
- с мутантов падает **мутантная ткань** — источник генов для экстрактора ДНК (замыкает петлю на генетику);
- вылов «красивых» мутаций — коллекционный слой, как разведение аксолотлей.

**Мутации игрока** (генотерапия, тир 4, `deep`): вводимые гены дают постоянные модификаторы атрибутов — жабры (дыхание под водой), ночное зрение, толстая кожа. Каждая несёт побочный ген (повышенный голод, уязвимость к огню). Снимаются только обратной терапией.

Все восемь сделаны. Эффекты объявляет контентный мод, поведение пишет `deep` (при отсутствии `deep` `core` эмулирует часть через ванильные эффекты).

| `toxicosis` ✓ | Тошнота и урон, сила зависит от концентрации яда | Передозировка, газ |
| `sedation` ✓ | −скорость, мобы не агрятся с дальних дистанций | Седативное (дротик для отлова мутантов) |

### 4.8 Жидкости в мире

v1 — псевдожидкости (см. 3.5): **кислотная лужа**, **токсичный шлам** (отходы реактора), **культуральная слизь** (разлив культуры — заражает). Растекаются ограниченно, испаряются или нейтрализуются (кислота + известь → безопасная соль). Перегрузка «отходами» без утилизации — ещё одна причина аварий и мутантов.

### 4.9 Конструктор мутаций

Мутация — набор **примитивов**, каждый пишется в коде один раз, дальше гены собираются данными (`data/biolab/gene/*.json`). Новый ген без нового кода, пока хватает примитивов.

| Примитив | Что меняет | Чем реализуется (см. 3.4) |
|---|---|---|
| `stats` | 9 атрибутов моба | `set_base` / `add_modifier` |
| `visual.tint` | Цвет всего моба | `body_color` |
| `visual.texture` | Скин целиком | `render::body` |
| `visual.overlay` | Слои поверх тела; флаги `full_bright` (светится) и `scroll` (текстура течёт) | `layers` |
| `visual.scale` | Масштаб, в том числе неравномерный, + хитбокс | `species_scale`, `Mob::bounds_at` |
| `goals` | Цели AI из библиотеки мода: плевок, прыжок, бегство от света, охота на животных, стайность, лояльность создателю | `trait Goal` |
| `aura` | Эффект на всех в радиусе | тик моба + 4.7 |
| `on_hit` | Эффект при ударе моба | урон моба |
| `on_death` | Взрыв, облако газа, лужа, распад на мелких | `drops::die` |
| `immunity` | Огонь, солнце, яды | тик эффектов |
| `drops` | Мутантная ткань и особые предметы | `drops::die` |
| `particles` | Облачка вокруг моба | API 11 |

```json
{ "id": "biolab:acid_glands",
  "stats":    { "attack_damage": 2 },
  "visual":   { "tint": "#7CFF4A", "overlay": "acid_spots" },
  "goals":    [{ "type": "biolab:spit", "projectile": "acid", "cooldown": 60 }],
  "on_hit":   [{ "effect": "biolab:acid_burn", "duration": 100 }],
  "on_death": [{ "spawn_fluid": "biolab:acid_puddle", "radius": 2 }],
  "cost": 3, "side_effect": "biolab:fragile_shell" }
```

**Путь игрока:** ткань моба → экстрактор ДНК → фрагменты генов → **сплайсер** (экран со слотами, у гена есть `cost`, суммарный лимит «стабильности»; перебор → нежизнеспособный или неконтролируемо мутирующий моб) → применение:
- **шприц с вектором** — уколоть живого моба, мутирует за несколько секунд;
- **клонирующий чан** — вырастить моба с заданным геномом;
- **генотерапия игрока** — только `stats`, `immunity`, `aura`, `on_hit`; вид и AI не для игрока.

**Ограничения вида** (3.4): геометрия и анимации остаются от ванильного вида, игроки без `deep` видят обычного моба.

### 4.10 Лаборатория: вольеры, штаммы, испытания

**Сделано (2026-11-01).** Штамм из четырёх характеристик живёт в чашке с культурой и в состоянии заражённого; инкубатор ведёт селекцию, микроскоп и подсказка показывают профиль, анализатор — штамм болезни. Вольер держит подопытного, пульт наблюдения показывает его состояние и журнал испытаний.

Болезни — **игровая абстракция**, набор чисел, без какой-либо реальной биологии.

**Штамм** = 4 характеристики 1–5 + список симптомов (ванильные эффекты) + цель (игроки / мобы / оба):

| Характеристика | В игре |
|---|---|
| Заразность | Шанс передачи при контакте, радиус |
| Инкубация | Тиков до симптомов |
| Тяжесть | Сила симптомов |
| Стойкость | Доз лекарства на курс |

**Блоки лаборатории:** вольер (подопытное животное внутри), пульт наблюдения (экран: список подопытных, стадия, характеристики), шлюз и дезинфектор (снижают риск утечки), инкубатор, микроскоп (показывает характеристики), центрифуга.

**Как игрок получает штаммы:**
1. **Из мира:** мазок с заражённого моба, болотная вода, заражённая зона.
2. **Селекция** (тир 3): образец у подопытного → инкубатор → характеристики смещаются случайно на ±1. Нужный профиль выводится за много поколений, с тупиковыми линиями. Медленно и по делу.
3. **Синтезатор штаммов** (тир 4, эндгейм): характеристики задаются прямо, но каждое очко стоит дорогих реагентов, а сумма ограничена «стабильностью». Высокая заразность требует низкой тяжести, и наоборот: универсального штамма не собрать.

**Испытания:** вводим препарат подопытному, пульт пишет в журнал, какая доза помогла, какая убила. Так находится курс лечения и состав вакцины.

**Применение:** вакцины и лекарства (основное); дротик со штаммом и заражённая зона против мобов — медленный контроль территории, не замена оружию.

**Последствия:**
- **Утечка:** разбитая колба, вольер без дезинфекции, отсутствие шлюза → болеет сам игрок, зараза расходится по мобам. Скорость зависит от заразности.
- **Расход подопытных:** животные гибнут, нужна ферма и уход.
- **Эпидемия** (событие): утечка сильного штамма заражает мобов в большом радиусе на несколько игровых дней.

Симметрия: чем опаснее выведенный штамм, тем опаснее он для своей же базы. Механика — про порядок и осторожность в лаборатории.

### 4.11 Единая система создания своего

Все три конструктора мода работают по одним правилам, поэтому игрок учится один раз:

| Конструктор | Что собирает | Из чего | Бюджет |
|---|---|---|---|
| Формульный синтезатор (4.1) | Вещество и препарат | Элементы | Стабильность формулы |
| Синтезатор штаммов (4.10) | Болезнь | Характеристики 1–5 | Стабильность штамма |
| Сплайсер генов (4.9) | Мутация, ГМ-растение | Гены-примитивы | Стабильность генома |

**Общие правила:**
1. **Бюджет вместо запретов.** Собрать можно почти что угодно, но сумма ограничена. Перебор — не отказ, а провал: вещество распадается, штамм вымирает, мутант нежизнеспособен.
2. **Побочка в комплекте.** Сильный компонент тащит за собой минус: мощный ген — хрупкость, высокая заразность — низкая тяжесть, биоактивная молекула — узкое терапевтическое окно.
3. **Сначала неизвестно.** Созданное не раскрывает свойства сразу. Нужно испытание: спектрометр для вещества, микроскоп для штамма, подопытный для действия на живом. До этого в журнале стоит «неопознано».
4. **Потом — твоё.** После испытаний запись закрывается: игрок даёт **своё имя**, и это имя дальше везде — в тултипе предмета, в журнале, в экранах машин.

**Сделано (2026-11-01).** Собранное вещество попадает в журнал **неопознанным**: формула видна, имени нет. Спектрометр закрывает запись — даёт каноническое имя из таблицы (34 вещества) или номер открытия — и печатает **чертёж**, предмет с формулой. Чертёж в синтезаторе задаёт цель: машина собирает ровно его состав и сам чертёж не тратит, так что повторять можно сколько угодно. (Исправлено 2026-11-01: по готовности синтезатор чистил все входы вместе с чертежом; теперь уходят только элементы — `synth_spent_slots`.) Своё имя даётся командой `/biolab name <имя>` для колбы в руке и дальше видно в подсказке; весь журнал читается командой `/biolab journal`.

**Чертежи и журнал.** Каждое удачное творение сохраняется в **лабораторный журнал** как чертёж: состав, свойства, результаты испытаний, дата открытия. Чертёж можно воспроизводить одной кнопкой (без повторного набора формулы), переименовывать и **копировать в книгу** — чтобы передать другому игроку или унести в другой мир.

Технически: чертежи хранятся в данных мода на мир, предмет-книга ссылается на запись по id. Если прототип M1 подтвердит запись `custom_data` в предмет, состав будет лежать прямо в предмете, и книга станет самодостаточной.

**Зачем это нужно.** Рецепты из вики перестают быть ответом: у каждого игрока своя таблица открытий и свои названия. Мод даёт правила, а контент игрок делает сам.

#### Ёмкость системы

Сколько всего можно собрать. Важно: **элементы ограничивают только вещества**, болезни считаются от характеристик, мутации — от числа генов.

| Конструктор | Формальных комбинаций | Различимых в игре | Чем ограничено |
|---|---|---|---|
| Вещества | ~86 млн формул до 12 атомов из 18 элементов, после проверки стабильности ~40 млн | Несколько тысяч профилей свойств, из них сотни полезных препаратов | Не элементами, а дискретностью шкал свойств: разные формулы дают один игровой эффект |
| Болезни | 625 комбинаций характеристик × 92 набора симптомов × 3 цели ≈ 170 тыс. | Несколько сотен штаммов | Числом характеристик и симптомов |
| Мутации | 30 генов по 4–6 слотов ≈ 760 тыс., с силой гена 1–3 — миллионы | Десятки тысяч, визуально — сотни | Числом генов, целей AI и текстур-слоёв |

**Настоящее дно — не математика, а контент.** Разнообразие ощущается через число примитивов, число целей AI (по поведению игрок и отличает мутантов) и число слоёв-текстур (без них десять мутантов выглядят одинаково).

**Ориентиры на первую версию:** 30 генов, 20 целей AI, 12 слоёв-оверлеев, 8 симптомов, 30 канонических веществ, 18 элементов. Дальнейший рост — добавление JSON-файлов без кода, пока хватает примитивов.

### 4.12 Внешний вид предметов: ревизия и переход на 3D

Сейчас каждый предмет мода — плоский спрайт 16×16, сгенерированный скриптом (`scratchpad/mktex.py`). Для прототипа этого хватало, но колба, шприц, ампула и тюбик мази — предметы, которые игрок держит в руке и разглядывает в инвентаре, и плоская иконка им не идёт. Переводим их в объёмные модели.

**Что умеет платформа.** Horizon читает ванильный формат моделей предметов целиком (`crates/horizon-assets/src/item_model.rs`, `item_bake.rs`): произвольные `elements` с поворотами, `display`-трансформы для всех шести положений (в руке от первого и третьего лица, в инвентаре, на земле, в рамке, на голове) и `gui_light: side`, который включает объёмное освещение в инвентаре. Нативный код не нужен — это данные контентного мода.

**Ревизия предметов.** Заодно проходим по всему списку: единые правила именования и подсказок, размеры стаков по смыслу (препараты по 16, элементы по 64, одноразовые шприцы по 16), понятные цвета по группам (элементы — по своему цвету, экстракты — по цвету вещества, препараты — по форме), общий силуэт у родственных предметов, чтобы они читались в хотбаре с одного взгляда.

#### Что переводим в 3D, а что нет

Предметов в моде 61. Объём нужен тем, у кого есть форма: стекло, металл, бумага — вещи, которые игрок вертит в руке. Горстка порошка и пятно ткани формы не имеют, и объёмными они станут только хуже.

**Объёмные (21 модель на 30 предметов).** Формы переиспользуются: у десяти препаратов одна геометрия и разный цвет.

| Форма | Предметы | Почему объёмная |
|---|---|---|

**Остаются плоскими (31 предмет).** Это не экономия, а осознанный выбор: у вещества нет формы, и спрайт честнее.

| Предметы | Почему |
|---|---|
| `element_*` (18 штук) | Горстка порошка: формы нет, цвет — единственное различие |

**Порядок работы.**
1. Разметка сделана: таблицы выше. Порошки элементов и бесформенные массы остаются спрайтами.
2. Сделать базовые формы из таблицы: 21 геометрия на 30 предметов. Каждая — набор `elements` с общей текстурной палитрой.
3. Подобрать `display`-трансформы, чтобы предмет не торчал сквозь руку и ровно смотрелся в инвентаре. Это самая кропотливая часть — проверять в игре, а не на глаз в редакторе.
4. Перегенерировать текстуры под развёртки моделей: сейчас картинка рисуется «как иконка», для объёмной модели нужны грани.
5. Варианты наполнения: у колбы и шприца содержимое красится по веществу — либо отдельным слоем модели, либо тонированием (цвет уже считается в `colour_of`).

**Инструмент.** Модели пишутся теми же питоновскими скриптами, что и текстуры: формы простые, а генератор удобнее ручного редактора, когда у десяти препаратов одна форма и разный цвет. Blockbench — только если понадобится сложная форма.

**Критерий готовности.** В хотбаре и в руке предметы мода выглядят как вещи, а не как наклейки; родственные предметы различаются с одного взгляда; ни один не проваливается сквозь руку и не вылезает за рамку инвентаря.

**Сделано (2026-11-01): геометрия по таблице, в игре ещё не проверена.** 17 форм из таблицы на 39 предметов (цифры «21 на 30» в заголовке таблицы с ней не сходятся — сделано по строкам таблицы). Всё генерирует `tools/mkitem3d.py`, проверяет `tools/check_item_models.py`.
- Объёмный предмет везде показывается моделью `item/3d/<форма>`: в руке, на земле, в рамке, на полке и в инвентаре. Определение `items/<id>.json` ссылается на неё напрямую. Плоский спрайт `item/<id>` сохранён для частиц и на случай отката (`FLAT_CONTEXTS` в генераторе: контексты, где снова нужна плоская иконка).
- Так решил пользователь (01.11.2026): сначала была схема подзорной трубы (плоская в инвентаре и на земле, 3D в руке), но выпавший шприц плоской картинкой и плоские иконки рядом с объёмными смотрелись чужими.
- Варианты формы — одна геометрия, цвет содержимого задаёт определение предмета оттенком `minecraft:constant` на гранях с `tintindex: 0` (цвета из плоских текстур). Культуры отличаются от агара ещё и текстурой колоний — модель-наследник `item/3d/petri_colonies`.
- Положение в руке — два пресета в генераторе: «стоячие» вещи (как блок: 75/45 от третьего лица) и «ручки» вдоль Y остриём вверх (углы ванильного `handheld`, пересчитанные с диагонального спрайта). Подстройка в игре — правкой пресета, а не каждой модели.

**Сделано (2026-11-01): ревизия предметов — имена, стопки, подсказки** (в игре ещё не проверено). Правила держат тесты в `runtime.rs`.
- *Имена.* Препарат — «<вещество>, <форма>» («Пенициллин, таблетка», «Яд, дротик»), экстракт — «Экстракт <чего>», элемент — названием элемента, машина и инструмент — существительным. Переименованы: «Зазубренный скальпель» → «Скальпель», «Неочищенный экстракт» → «Экстракт культуры», «Препарат» → «Сыворотка», «Чашка с культурой» → «Культура», «Ослабленный штамм» → «Ослабленная культура», «Обезболивающая мазь» → «Обезболивающее, мазь», «Дротик с седативным/ядом» → «Седативное/Яд, дротик». Английское имя есть у каждого предмета, ключи `ru_ru` и `en_us` совпадают.
- *Подписи предметов с данными* — «<имя предмета>: <данные>»: «Колба: вода, 250 мл» (знакомое вещество по имени, иначе формулой), «Фрагмент ДНК: Хитин ++», «Культура: З2 И3 Т2 С1», «ГМ-урожай: …», «Чертёж: вода (H2O)». Подпись выводится из данных (`item_label`), тик инвентаря переписывает её у колбы, фрагмента, культуры и урожая — старые предметы тоже.
- *Стопки.* 1 — всё со своими данными (колба, фрагмент ДНК, культура, чертёж, ГМ-урожай: меню Horizon сливает стопки только по id, разные гены слиплись бы), инструменты (скальпель, анализатор, микроскоп, журнал) и вёдра; 64 — сырьё (элементы, мутантная ткань, плесень); 16 — препараты, шприцы, дротики, экстракты и расходники (агар, палочка, бинт, раствор, мутаген, ослабленная культура). Машины — как у шаблона-блока (64). Грядка кладёт плоды урожая по одному в свободные места.
- *Подсказки* — одна-две строки под строками данных, серо-голубым: что делает и как применить («ПКМ — …», «ПКМ по мобу — …», «ПКМ по блоку — …», у машины «вход → выход»), с заглавной, без точки, до 48 знаков. Таблица `ITEM_HINTS` в `runtime.rs`, элементам строку собирает `item_hint` («Символ Fe: сырьё для синтезатора»). Тест требует подсказку у каждого предмета из `assets/biolab/items/` (или запись в `HINTS_SKIPPED`) и сверяет её с кодом: шприц говорит «по мобу» ровно тогда, когда действует на моба, «Пресс» у экстракта — когда есть рецепт пресса.

### 4.13 Книга-руководство

Мод большой: девять машин, восемнадцать элементов, семь веществ, восемь генов, штаммы. Разбираться в этом по вики — не тот опыт, который хочется дать. Поэтому при первом входе в мир игрок получает в рюкзак **«Журнал лаборанта»** — книгу, из которой понятно, что для чего, что из чего крафтится и с чего начинать.

**Что внутри.** Разделы по подсистемам: первые шаги (стол, колба, мазок, инкубатор), машины (что делает каждая, чем топится, что принимает), химия (таблица элементов, откуда добывается, как собрать вещество в синтезаторе), фармакология (вещества, формы, окно и привыкание, чем лечить передозировку), генетика (ткань, экстрактор, фрагменты, сплайсинг, чан, генотерапия), штаммы (четыре характеристики, селекция, вакцина), опасности (кислота, мутаген, перегрев реактора, утечка). У каждого предмета — из чего крафтится, прямо в тексте.

**Сделано (2026-11-01): карта исследований, как в Thaumcraft.** Журнал — не книга со страницами, а карта: пять наук-вкладок (основы, химия, микробиология, фармакология, генетика), в каждой узлы, связанные линиями, всего 47 (два добавлены в 4.15). Узел загорается сам, когда игрок сделал что-то новое: у него в инвентаре оказался предмет (плесень, культура, фрагмент ДНК, машина), в журнале появилось или опозналось вещество, он заразился, принял лекарство, получил ген, сорвал курс. Новое приходит в чат: «Журнал лаборанта: новая запись «Плесень»».

Состояния узла: **изучен** (золотая рамка), **доступен** (все предшественники изучены — фиолетовая мерцающая рамка, подсказка у курсора говорит, как открыть), **вопрос** (часть предшественников изучена или игрок забежал вперёд и изучил потомка), **скрыт**. Щелчок по изученному или доступному узлу открывает запись на пергаменте: заголовок, текст с переносом, ряды иконок и рецепты — сетка 3×3 для верстака, такая же сетка с подписью «на лабораторном столе» для стола и строка «вход → машина, время → выход» для машин мода.

**Как это сделано.**
- Таблица узлов, условия, раскладка экрана, попадание мышью, разбор записей и JSON-рецептов — чистая логика в `biolab_core` (раздел «Карта исследований» в `runtime.rs`), под тестами: таблица согласована, каждый предмет существует в контенте, у каждого узла есть запись и все её рецепты разбираются.
- Изученное хранится у игрока (`research=` в файле состояния, по id узлов), сервер раз в секунду проверяет инвентарь и журнал и шлёт клиенту маску по каналу `biolab_core:research`.
- Экран — в `biolab-deep`: журнал в руке открывает **пустой ванильный экран книги**, а пять перехватов с отменой (`remote_use_item`/`use_book` — открыть, `draw_book` — рисовать, `book_click` — мышь, `book_input` — клавиши) подменяют его своим. Ванильный экран даёт даром свободный курсор и то, что мир не реагирует на клики; запрос на сервер не уходит.
- Тексты записей — `data/biolab/research/ru.txt`: блок `= <id узла>`, страницы через `---`, разметка `# заголовок`, `@item <id>…`, `@craft <файл рецепта>`. Правятся без пересборки.
- **Записи по одной схеме (2026-11-01):** что это, как получить (`@craft`), что делать — конкретные действия игрока (ПКМ по мобу, ПКМ в воздух, что положить в какой слот), где виден результат, и что открыть дальше. Числа взяты из кода. Первая запись — «путь лаборанта» по шагам. Подсказки узлов говорят действие.
- **Вёрстка страницы — одно правило на отрисовку и тест** (`page_area`, `page_rows`, `PageRow::height`, `rows_fitting` в `runtime.rs`): перенос по словам, высоты строк и низ страницы над кнопками. Отрисовка меряет текст шрифтом игры, тест — оценкой с запасом (`estimated_text_width`). Тесты: каждая страница влезает в экран 427×240 и начинается с заголовка, у каждого предмета с рецептом есть `@craft` в какой-нибудь записи, подсказки узлов не шире 270 пикселей.
- Текстуры экрана (поле, пергамент, рамки узлов, вкладки) — `textures/gui/research/`, рисуются `native_sprite`; без них экран рисуется заливками.

Управление: мышь — вкладки, узлы, «<», «>», «к карте» (щелчок мимо записи тоже возвращает к карте); клавиши — 1–5 науки, ←/→ листают запись, Esc закрывает запись, потом журнал.

Книга приходит при первом входе в мир (отметка в состоянии игрока) и перевыпускается командой `/biolab book`; изученное хранится у игрока, а не в книге, так что новая книга знает всё то же.

### 4.14 Вкладка творческого инвентаря

Предметов в моде 75 вместе с блоками, и искать их среди ванильных — мучение. Своя вкладка **BioLab** собирает их в одном месте и в осмысленном порядке: сначала лабораторный стол, потом машины, инструменты, элементы, сырьё и вещества, лекарства, генетика и в конце — жидкости с вёдрами. Вкладка читается как путь игрока, а не как россыпь.

**Как это сделано.** Вкладки игра берёт из экспорта ванильного творческого инвентаря, и предметов мода там нет — брать их оттуда нечего (проверено: вкладка выходила пустой). Поэтому список собирается скриптом из файлов контента в таблицу `biolab_tab::ITEMS`, а сама вкладка дописывается в `Creative::rebuild` из `biolab-deep`. Колонка — пятая в нижнем ряду: шестая занята «инвентарём выживания», и вкладка пряталась под ним.

### 4.15 Ревизия машин

Машин двенадцать, и в книге это видно сразу: восемь одинаковых кубов, которые различаются только цветной точкой сверху. Плюс у половины почти нет работы.

**Сколько у кого рецептов сейчас:** перегонный куб 23, пресс 4, инкубатор 3, реактор 3, ферментер 2, центрифуга 2, экстрактор 1. Синтезатор, спектрометр, клонирующий чан, вольер и пульт рецептов не имеют вовсе — они работают своей логикой, и это нормально.

**Что не так.** Ферментер, центрифуга и экстрактор стоят в цепочке ради одного-двух шагов: игрок строит блок, пользуется им дважды и забывает. Роли у них размыты — все трое «что-то делают с жидкостью».

**Как чиним (спецификация, 2026-11-01).**

*Роли.* У каждой машины своя ось:

| Машина | Ось | Что меняется |
|---|---|---|
| Перегонный куб | неживое → элементы | остаются 18 элементов, агар и фосфор из ткани; три растительных экстракта уходят в ферментер |
| Ферментер | живое → экстракты | плесень → пенициллин, культура → сырой экстракт, листва берёзы → салицилат, мак → седативное, какао → кофеин, паучий глаз → маринованный паучий глаз, пшеница → питательный бульон |
| Центрифуга | разделение | 1 вход и 4 выхода (меню воронки, 5 слотов). Рецепт даёт основной выход и побочный (`"byproduct": {"id", "count"}`): сырой экстракт → лекарство, паучий глаз → яд, сгусток магмы → слизь + огненный порошок, гравий → кремень + песок, сверкающий ломтик арбуза → ломтик + самородок золота. **Разложение колбы**: вещество → его элементы по выходам, колба возвращается с водой; воду не разлагает (иначе бесконечный водород), больше трёх видов элементов не берёт; время 40 + 10 × атомы |
| Экстрактор | ДНК из живого | ткань мутанта → случайный ген (как было); из животных — свой ген: кроличья лапка → прыгучие ноги, кость → плотная кость, светящийся чернильный мешок → биолюминесценция, сгусток магмы → термостойкость, щиток черепахи → жаберные складки, гнилая плоть → некроз (поле `"gene"` и `"strength"` в рецепте); урожай ГМ-грядки → фрагмент с самым сильным геном урожая |
| Реактор, пресс, инкубатор | без изменений | — |
| Лабораторный стол | точная сборка | верстак лаборатории: шприцы и их наполнение, дротики, аэрозоли, мазь, анализатор, микроскоп, скальпель, палочка, бинт, мутаген, питательный раствор собираются только на нём. Сетка 3×3 (0–7 входы, 8 — выход), свой тип рецептов `biolab:lab_bench`: `ingredients` списком, `result`, `time` (40–60 тиков). Собирает, когда во входах ровно набор рецепта — каждая запись в своём слоте, порядок любой, лишнего нет; стопка в слоте хватает на несколько сборок. Машины, колба, грядка и вёдра остаются на верстаке |

Слот топлива (1) есть у всех машин на меню печки, но нужен только чану (питательный раствор). У остальных он прячется с экрана и убирается из входов для воронок.

*Контракт слотов данных* (`entity.data`, 16 бит, константы `DATA_*` в `runtime.rs`). Общие 0–3: пламя, его максимум, прогресс, время рецепта. Дальше по машинам:
- реактор: 4 — температура, 5 — цель нагрева (−1 — нет источника), 6–7 — диапазон текущего рецепта (0, 0 — без диапазона);
- синтезатор: 4 — статус (0 пусто, 1 неустойчиво, 2 устойчиво, 3 не совпадает с чертежом), 5–22 — число атомов каждого из 18 элементов по порядку `ELEMENTS`;
- спектрометр: 4–21 — состав колбы во входе по порядку `ELEMENTS`;
- клонирующий чан и экстрактор: 4 — номер гена в `GENES` (−1 — нет), 5 — сила;
- инкубатор: 4–7 — штамм культуры во входе (заразность, инкубация, тяжесть, стойкость; нули — нет культуры);
- лабораторный стол: 4 — что соберётся из выложенного: номер результата в `BENCH_RESULTS` (−2 — входы пусты, −1 — нет такого рецепта, −3 — рецепт есть, но его результата нет в таблице).

*Силуэты* (отдельная задача, после экранов): вместо куба с цветной крышкой — модель из `elements`: у перегонного куба змеевик, у ферментера бак с люком, у центрифуги барабан, у реактора трубы и манометр, у пресса плита на станине, у спектрометра призма и шкала.

**Сделано (2026-11-01): машины в 3D** (ещё не проверено в игре). Модели, текстуры и blockstates всех 12 машин и стола генерирует `tools/mkblock_machines.py`, проверяет `tools/check_models.py`. Правила, которые следуют из того, что для игры машина — сплошной куб (соседи не рисуют прилегающие грани):
- у модели полное основание 16×16 и стенки по краям, детали внутри 0…16 по X/Z, вверх не выше 20;
- `cullface` только у низа и у граней во всю сторону блока: частичная грань на границе рисуется всегда, иначе сквозь окно соседней машины был бы провал;
- `lit=true` — модель `<машина>_on`: светящиеся части (`light_emission`, текстура `_lamp_on`), у спектрометра появляются лучи;
- родитель `minecraft:block/block` даёт `display` для инвентаря и руки.

**Сделано (2026-11-01): роли и контракт данных.** Рецепты переложены по осям, центрифуга раскладывает выходы по четырём слотам и разлагает колбы, экстрактор берёт гены из рецепта и из урожая, машины заполняют свои слоты данных. Решения — в `runtime.rs` (раздел «Роли машин»: `decompose`, `plan_outputs`, `recipe_gene`, `strongest_gene`, `synth_status`…), под тестами; хук тика машины только двигает предметы.
- Время разложения то же, что у синтезатора: 40 + 10 × атомы, с потолком 600 тиков.
- Выход машины сливается со стаком только если у обоих нет своих данных: колба с водой, фрагмент и культура ложатся в пустой слот. Заодно закрыта старая дыра: культура (стопка 16) при культуре в выходе съедала вход и пропадала.
- Последний ген экстрактора хранится в сейве машины (`biolab_last_gene`): числа меню не сохраняются, и после перезахода экран показал бы гигантизм (ген номер 0).
- В журнале два новых узла: «Разделение» (химия) и «Гены животных» (генетика), всего 47.

**Сделано (2026-11-01): лабораторный стол.** Стол — машина на сетке 3×3 со своим типом рецептов; 19 рецептов точных вещей переехали с верстака на него с тем же количеством результата. Анализатор на верстаке занимал все девять клеток, а входов у стола восемь, — стекла в нём теперь шесть, а не семь. Сопоставление входов с рецептом (`bench_match`: паросочетание, записи с тегами и списками не путаются) и таблица результатов для экрана — раздел «Лабораторный стол» в `runtime.rs`, под тестами: таблица сверяется с рецептами в `content/` и с именами в языковом файле, а на верстаке не осталось рецептов точных вещей. Экран: табло с иконкой и именем того, что соберётся (длинное имя бежит строкой), или «Нет такого рецепта», справа лампа и шкала. В журнале рецепты стола рисуются сеткой с подписью «на лабораторном столе».
- Меню мод-блока открывается только у блока, чей шаблон сам открывает меню (печь, сетка, верстак…, `interact.rs` в Horizon), поэтому шаблон стола — `minecraft:crafting_table`: у него тоже нет `facing`, а меню мода Horizon проверяет раньше ванильного верстака.

### 4.16 Свои экраны машин

Сейчас все машины открывают ванильное меню печки: три слота и шкала пламени. Это скрывает половину того, что машина делает, — температуру реактора, формулу синтезатора, рост клона, профиль штамма в инкубаторе.

Платформа даёт модам свои экраны поверх их меню (API 19–20: `native_screen` задаёт раскладку слотов — слот без позиции выпадает из меню, `native_screen_draw` рисует, `native_screen_tooltip` — подсказки, `native_screen_click` — кнопки). Меню остаётся ванильным по числу слотов (печка, воронка, сетка 3×3), а всё, что видит игрок, — наше.

**Спецификация (2026-11-01).** Общий вид: лабораторная панель (сталь с бирюзовой подсветкой) 176 пикселей шириной, иконка машины и название, инвентарь игрока снизу. Шкала прогресса у каждой машины своя, плюс свой прибор:
- перегонный куб — змеевик, по которому бегут капли;
- ферментер — бак с пузырями;
- центрифуга — вход и четыре выхода, барабан крутится;
- реактор — градусник с отметкой цели нагрева, полосой диапазона рецепта и красной зоной перегрева;
- синтезатор — набранная формула и её имя, цвет по статусу;
- спектрометр — 18 полос спектра с символами элементов;
- клонирующий чан — силуэт клона растёт, подписан ген;
- инкубатор — четыре полоски штамма;
- экстрактор — имя последнего гена;
- пресс — плита опускается по ходу прогресса.

Подсказки над приборами говорят числа словами: «Температура 58 °C, рецепту нужно 55–65 °C».

**Сделано (2026-11-01).** У всех десяти машин свой экран: стальная панель с бирюзовой подсветкой, иконка и название, лампа работы, свой прибор и шкала, подсказки с числами. Проверено в игре на реакторе (градусник, цель нагрева, диапазон рецепта), синтезаторе, спектрометре (спектр глюкозы по H, C, O), центрифуге (вход и четыре выхода) и клонирующем чане (два входа, силуэт клона). Раскладки, геометрия приборов и тексты подсказок — раздел «Экраны машин» в конце `runtime.rs`, под тестами; хуки — `screen_layout.rs`, `screen_draw.rs`, `screen_tooltip.rs`; текстуры — `textures/gui/machine`, генератор — `tools/mkgui_machine.py`.

Ограничение платформы: у меню `generic_3x3` (синтезатор) и `hopper` (центрифуга) слоты расставляет сам Horizon до вопроса к моду, поэтому у этих двух машин слоты стоят на ванильных местах, а приборы нарисованы вокруг них.

### 4.17 Операционная: ткань с живого мутанта

Ткань мутанта больше не падает при убийстве. Её срезают скальпелем с живого мутанта, уложенного на операционный стол (решение пользователя, 01.11.2026). Цепочка: **усыпить → погрузить на носилки → уложить на стол → срезать плоть**. Так в одну линию встают снотворное, носилки, стол и скальпель, а мутант из «лута» становится пациентом.

**Предметы и блоки.**
- `biolab:stretcher` — носилки, стопка 1. Пустые носилки: ПКМ по мутанту под снотворным (эффект `biolab:sedation`) убирает моба из мира и записывает его в носилки (`custom_data` → `biolab_patient`: вид, геном, здоровье, маска срезанных конечностей, имя). Неспящего погрузить нельзя («Сначала усыпите»). На занятых носилках подсказка показывает, кто на них. Обычного моба (не мутанта) тоже можно погрузить.
- `biolab:operating_table` — операционный стол, блок. ПКМ занятыми носилками по столу: моб появляется лежащим на столе, пристёгнутым, носилки пустеют. Пока моб на столе, его держат на месте (как вольер, телепортом) и не дают проснуться (снотворное подновляется). Пустыми носилками по мобу на столе — снять его обратно на носилки. Сломали стол — моб свободен.
- Скальпель: ПКМ по мобу **на столе** срезает следующую конечность — 1 ткань (с теми же данными, что раньше давало убийство), урон и кровотечение (`biolab:bleeding`). Конечностей четыре (у видов без конечностей — слизни, гасты, рыбы, кальмары и т. п. — срезать нечего, кроме одного куска тела). Когда всё срезано: «Плоти не осталось».

**Последствия.** Каждая срезанная конечность замедляет моба на 10 % (когда он уже не на столе). Ген регенерации отращивает одну конечность в минуту.

**Контракт меток на мобе** (модификатор `FollowRange` с нулевой прибавкой, как метки генов — их видит и сервер, и отрисовка):
- `biolab:surgery/table` — моб лежит на столе;
- `biolab:surgery/flayed/0` … `/3` — срезана конечность с этим номером;
- `biolab:surgery/slow` — модификатор скорости за срезанные конечности (`MovementSpeed`, `add_multiplied_base`).

**Номер → часть модели** (для отрисовки): гуманоиды 0 `right_arm`, 1 `left_arm`, 2 `right_leg`, 3 `left_leg`; четвероногие 0 `right_front_leg`, 1 `left_front_leg`, 2 `right_hind_leg`, 3 `left_hind_leg`; иначе — первые четыре части модели, в имени которых есть `arm` или `leg`, в порядке модели. Срезов делается столько, сколько у вида конечностей по серверной таблице (до 4).

**Вид.** Моб на столе лежит на спине (поворот модели на 90°). Срезанная конечность — тонкая и цвета кости: «плоти нет». Если перекрасить одну часть модели не выйдет, конечность просто истончается.

**Сделано (2026-11-01): вид** (ещё не проверено в игре). Метки читаются прямо на мобе (`has_modifier` по `FollowRange`): в одиночной игре сервер и отрисовка работают с одним списком мобов, так что метка видна в тот же кадр. Код — lib-модуль `biolab_surgery` (`native/biolab-deep/mixins/biolab_deep/surgery.rs`, чистая часть под тестами).
- *Лёжа*: RETURN на `species_scale` (`scale.rs`, поверх масштаба генома) домножает матрицу «лёжа». Габарит модели в покое считается по её частям (кэш по модели); высокая модель (гуманоид, курица, крипер) поворачивается на 90° вокруг X мордой вверх, длинная (корова, паук) — на 90° вокруг Z, на бок. Потом модель сдвигается так, чтобы нижняя точка легла на верхнюю грань стола (зазор 0,02 блока от мерцания), а середина габарита — над центром стола. Броня, предметы в руках и слои поворачиваются вместе с телом.
- *Срезанные конечности*: HEAD на `anim::setup` прячет их во всех проходах (тело и его слои — броня, шерсть, одежда: на кости ни плоти, ни рукава). RETURN на `render_visible` дорисовывает их отдельным проходом: своя поза (анимация с флагом «проход костей»), у срезанных частей масштаб по ширине и глубине ×0,5, все остальные части без своих граней (`skip_draw`), текстура кости `biolab:gui/surgery/bone` из общего атласа (запасной вариант — текстура моба с оттенком кости), красная вспышка удара — как у тела. Конечность, которую прячет сама анимация (сложенные руки разбойника), костью не рисуется. Вставить код сразу после `anim::setup` внутри `render_visible` нельзя: там замыкание `draw_body`, а в функции с замыканием инструмент миксинов допускает только HEAD и RETURN.
- *Модели*: стол (`tools/mkblock_machines.py`) — стальной стол на четырёх опорах с тумбой (для игры блок — сплошной куб), полотно с подушкой и двумя ремнями с пряжками, над изголовьем (север) лампа на кронштейне, светится всегда; столешница на y = 16, без `facing`. Носилки (`tools/mkitem3d.py`, форма `stretcher`) — две жерди с полотном и красным крестом, ручки в резине, распорки и ножки; объёмные везде.
- Ограничение: клиент чужого сервера меток не получает (как и геном), там моб будет стоять и с конечностями.

### 4.18 Многоблочные установки (дизайн, 01.11.2026)

Одиночные машины — это лаборатория новичка. Большие установки — производство: игрок строит их из блоков, и они делают то, что одной машине не под силу. Выбраны четыре: ректификационная колонна, биореактор, генный секвенатор и карантинная камера. Делаем после операционной (4.17), по одной, на общем каркасе.

#### Общий каркас
- **Части.** Корпус (`biolab:casing`), стекло установки, порты входа и выхода (к ним цепляются воронки), **контроллер** — блок с блок-сущностью, меню и своим экраном (как у машин, 4.16).
- **Сборка.** Контроллер раз в секунду сверяет блоки вокруг со схемой установки (схема — таблица в `runtime.rs`, проверка — чистая функция с тестами). Чего не хватает, показывает экран контроллера: «Нет 3 блоков корпуса: 2-й ярус, слева». Сломали блок — установка разобрана, работа встаёт, содержимое остаётся в контроллере.
- **Вид собранной установки.** Модель блока может выходить за его границы на целый блок в каждую сторону (`elements` от −16 до 32). Поэтому контроллер в центре грани рисует общий вид установки, а блоки корпуса при сборке переключаются в «склеенный» вид без швов. Переключение — свойство блока, которое меняет код (`native_set_block_property`, как `lit` у реактора). Шаблон корпуса с подходящим свободным свойством подбираем на прототипе.
- **Порты.** Вход и выход — отдельные блоки со слотами (`ModContainer`): контроллер забирает из входных и кладёт в выходные. Так автоматизация воронками работает без особых правил.
- **Журнал.** У каждой установки свой узел и запись со схемой по ярусам (ряды иконок блоков).

#### 1. Ректификационная колонна — большая перегонка
Башня 1×1 высотой от 3 до 7 блоков: внизу **куб-кипятильник** (контроллер) над источником тепла (те же источники, что у реактора), выше — **тарелки** (секции колонны), на вершине — **конденсатор**. Одна загрузка расходится сразу на несколько продуктов: каждая тарелка отдаёт свою фракцию, лёгкие выше, тяжёлые ниже. Чем выше башня, тем больше фракций выходит за раз.
- Рецепты типа `biolab:column`: вход и упорядоченный список фракций. Например, гнилая плоть → азот, углерод, фосфор, сера; ламинария → кислород, йод, натрий, калий; кость → кальций, фосфор.
- Выигрыш перед перегонным кубом: несколько элементов с одного предмета и больший выход. Нужна, когда синтезатору не хватает сырья.
- Первая в очереди: самая простая схема (одна вертикаль). На ней отлаживаем каркас.

#### 2. Биореактор — промышленный ферментер
Куб 3×3×3: стенки из корпуса и стекла, внутри пусто (там среда), контроллер в середине грани, три порта — вход, выход, бульон.
- Варит **партией**: до 8 предметов по рецептам ферментера и инкубатора сразу, быстрее одиночных машин.
- Ест питательный бульон: одна порция на партию. Держит температуру 30–40 °C (источник тепла под ним, перегрев портит партию).
- **Заражение партии.** С небольшим шансом партия скисает в слизь, если реактор стоит не в карантинной камере (связь с пунктом 4).

#### 3. Генный секвенатор — генетика без ограничений
Установка 3×2×3: контроллер-консоль, две стойки секвенаторов, монитор, порты. Закрывает то, чего генетике сейчас не хватает: гены вживляют по одному фрагменту, а убрать ген нельзя.
- **Сборка вектора:** 2–3 фрагмента → один вектор с несколькими генами (стабильность — те же 3 гена и сумма цен до 6). Вектор вживляется одним уколом.
- **Антисмысловой вектор:** фрагмент → вектор, который при уколе **удаляет** этот ген у моба или у игрока. Это обратная генотерапия.
- **Полное чтение генома** моба, лежащего на операционном столе рядом с установкой: все гены, сила, стабильность — на экране секвенатора.
- Расходник — фосфор (нуклеотиды) и питательный бульон.

#### 4. Карантинная камера — чистая комната
Комната любой формы до 9×9×5 из **чистых панелей** и стекла, с **фильтром** (контроллер) и **шлюзом** (две двери подряд). Контроллер проверяет, что комната замкнута: заливкой изнутри, без дыр наружу.
- Внутри нельзя заразиться: близость зомби, лужи и аура мутантов не действуют. Машины внутри не «скисают» (биореактор).
- **Новый риск снаружи.** Работа с тяжёлым штаммом (тяжесть 4–5, выведенным селекцией) вне карантина приводит к утечке: заражаются мобы и игроки рядом. Так камера становится нужной для поздней микробиологии, а не украшением.
- Фильтр изнашивается: сменный расходник из угля и шерсти.

#### Порядок
Каркас и колонна → биореактор → карантинная камера → секвенатор. Карантин раньше секвенатора, потому что от него зависит биореактор.

## 6. Вертикальный срез (MVP)

**Сделано (2026-11-01).** История проходится целиком, вместе с последним шагом: курс, который бросили на полпути, делает штамм устойчивее — следующая доза снимает меньше.

Цель — одна сквозная история, которая задевает все три базовые системы. **История Флеминга:**

1. Игрок ест гнилую плоть → заражается **трупной лихорадкой** (инкубация → слабость и голод).
2. Из ламинарии в перегонном кубе получает **агар** → чашка Петри.
3. Мазок с заплесневевшего хлеба (хлеб + время в сыром месте) → **инкубатор** → культура пеницилла.
4. **Ферментер** → неочищенный пенициллин → **центрифуга** → чистый.
5. **Шприц** → инъекция → концентрация в крови → болезнь отступает. Если прервать курс — штамм становится устойчивым.

**Состав MVP**
- Контент: ~12 предметов (палочка, чашка Петри, агар, колба, шприц, 3–4 вещества, хлеб с плесенью, культура), 4 блока-машины (перегонный куб, инкубатор, ферментер, центрифуга), рецепты, локализация ru/en.
- Логика: общий каркас машины (block entity + слоты + экран + свой тип рецептов), 1 болезнь со стадиями, фармакокинетика одного вещества, HUD анализатора, команды отладки `/biolab infect|blood|cure` — все три на месте.

## 8. Открытые вопросы

1. **Запись `custom_data` в стек** из нативного кода — одна универсальная колба или по предмету на вещество. *Прототип первым делом.*
2. **Сохранение состояния игроков** (болезни, кровь) — на мир. Как получить идентификатор мира в `core`?
3. **Можно ли таргетить крейты кроме `horizon_client`** (`horizon_client_render`, `horizon_world`)? Все известные моды хукают только `horizon_client::`. Проверить `horizon-mixins plan`.
4. **Генерация чанка и мутанты:** у моба из сейва id меняется. Проверить, что ленивое чтение генома из `persist.raw` срабатывает до первого тика.
5. **Мультиплеер:** клиент без мода видит мутантов ванильными. Требовать мод на сервере и клиентах или допускать «ванильный» вид?
6. **Баланс опасности:** частота болезней и мутантов, настройка сложности в `config/biolab.json`.
7. **Сохранение генома мутанта — решено (2026-10-31).** Функции сохранения моба (`entity_nbt::mob_to_nbt`/`mob_from_nbt`) не принимают ни одного вида хука, поэтому геном хранится в том, что ванилла сохраняет сама, — в модификаторах атрибутов:
   - при рождении мутант получает прибавки и **метку** — модификатор дальности преследования с нулевым значением и именем гена (`biolab:gene/gigantism/3`); ванилла пишет его в NBT вместе с остальными;
   - ванилла при загрузке читает только базы атрибутов, поэтому стабильный хук `native_mobs_joined` (бинарник, где виден сырой NBT `persist.raw`) возвращает наши модификаторы и сохранённое здоровье;
   - отрисовка в lib-крейте узнаёт геном по метке на самом мобе, без общей памяти с бинарником.
   Проверено перезапуском: у мобов сменились id, а геномы и здоровье остались прежними (новый бросок дал бы другие).
