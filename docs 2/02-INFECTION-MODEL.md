# 02 — Модель заражения: хосты, доза, стадии, иммунитет, передача

## 1. Профиль хоста (HostProfile)

Объект датапак-реестра `biohazard:host_profile`. Привязывается к **тегам типов
сущностей**, а не к конкретным классам — это ключ к совместимости: мобы из чужих
модов автоматически попадают в систему, если их теги совпадают, и моддер может
добавить свои мобы одним тегом без Java.

```json
{
  "entity_tag": "biohazard:host/livestock",
  "receptors": [
    { "receptor": "biohazard:receptor/ace_like", "density": 1.0 },
    { "receptor": "biohazard:receptor/gut_epithelium", "density": 0.4 }
  ],
  "immune_strength": 0.5,
  "body_mass": 1.0,
  "metabolic_rate": 1.0,
  "shedding_multiplier": 1.2,
  "can_carry_asymptomatically": true,
  "death_behavior": "corpse_contaminates",
  "breeding_transmits": true
}
```

### Базовые профили

| Профиль | Иммунитет | Особенности |
|---------|-----------|-------------|
| `host/player` | 0.7 (растёт с иммунной памятью) | Полный UI симптомов, своя диагностика, хронические состояния переживают смерть (конфиг) |
| `host/villager` | 0.45 | Профессии ломаются, деревня как узел эпидемии, можно лечить за репутацию |
| `host/livestock` | 0.5 | Корова, свинья, овца, курица, лошадь, кролик. Основной материал для пассажа. Вертикальная передача потомству |
| `host/wild_mammal` | 0.55 | Волк, лиса, панда, медведь. Разносят далеко, их не контролируешь |
| `host/avian` | 0.4 | Курица, попугай. Высокий `shedding`, «птичий грипп» как явление |
| `host/arthropod` | 0.3 | Паук, пчела, серебрянка. **Переносчики.** Пчёлы летают далеко и посещают много блоков |
| `host/aquatic` | 0.5 | Разносят по водоёмам |
| `host/undead` | **0.0** | Нет иммунитета вообще. Никогда не выздоравливают. Вечный резервуар инфекции |
| `host/illager` | 0.5 | Разносят между аутпостами и рейдами |
| `host/nether_fauna` | 0.6 | Требуют `env/thermostable` |
| `host/plant` (блоки) | — | Особая модель: не сущность, а блок. См. [05-WORLD-CONTAMINATION.md](05-WORLD-CONTAMINATION.md) |
| `host/golem` / `host/construct` | — | **Невосприимчивы.** Железный голем, снежный голем, незаражаемые мобы. Явный тег-исключение `biohazard:immune` |

**Явный тег `biohazard:immune`** — чтобы владельцы серверов и моддеры могли
исключить мобов (боссов, питомцев, NPC из квестовых модов) из системы одной
строкой.

## 2. Рецепторная модель: честный межвидовой барьер

Вирус не «заражает мобов из списка». Он связывается с **рецептором**, а рецепторы
есть у хостов с разной плотностью.

```
affinity(strain, host) = max по генам тропизма g:
    receptorDensity(host, g.receptor)
  × (g.expression / 100)
  × structureBindingModifier(strain.structure, g.receptor)
```

Что это даёт:

1. **Объяснимость.** Игрок видит в UI матрицу: «штамм связывается с
   `ace_like` на 80%, у коровы плотность 1.0 → аффинность 0.8; у игрока
   рецептор другой (`ace_like_primate`) → аффинность 0». Понятно, почему не
   заражает.
2. **Естественная зоонозная механика.** Рецепторы примата и млекопитающего
   похожи, но не идентичны. При пассаже через млекопитающего экспрессия
   подстраивается, и есть **малый шанс мутации в сторону соседнего рецептора**.
   Так возникает реальный межвидовой переход — не по скрипту, а по симуляции.
3. **Причина строить зверинец.** Разные хосты = разные рецепторы = разные
   направления эволюции.

### Карта рецепторов

| Рецептор | У кого высокая плотность | Соседние (куда может мутировать) |
|----------|--------------------------|----------------------------------|
| `receptor/ace_like` | Млекопитающие | `ace_like_primate` (шанс низкий!) |
| `receptor/ace_like_primate` | Игрок, житель, иллагер | `ace_like` |
| `receptor/sialic_avian` | Птицы | `ace_like` (через свинью как «миксер») |
| `receptor/chitin_gut` | Арthropod | `chitin_wall` |
| `receptor/chitin_wall` | Грибы | `chitin_gut`, `cellulose` |
| `receptor/cellulose` | Растения | `chitin_wall` |
| `receptor/necrotic_tissue` | Незадед | — (тупиковая ветвь, но вечный резервуар) |
| `receptor/gill_epithelium` | Водные | `ace_like` |
| `receptor/thermal_endotherm` | Нижний мир | — |

**Свинья как «смешивающий сосуд»** — реальный факт вирусологии: у свиней есть
рецепторы и птичьего, и человеческого типа. В моде: `host/livestock/pig` имеет
обе плотности по 0.6 → **единственный хост, где возможна реассортация между
птичьими и приматными линиями**. Это даёт конкретное знание, которое игрок
открывает и использует. Отличная деталь.

## 3. Доза: экспозиция ≠ заражение

**Критически важный дизайн.** Контакт с вирусом не заражает мгновенно. Копится
доза.

```
InfectionState (аттачмент на сущности)
├── activeInfections: List<ActiveInfection>
├── immuneMemory: List<ImmuneMemoryEntry>
├── exposure: Map<UUID strainId, float dose>   // накопленная доза по штаммам
└── chronicConditions: List<ChronicCondition>
```

Каждый тик проверки (не каждый игровой тик — см. производительность):

```
доза += источникЭкспозиции
      × (1 − защитаКостюма[вектор])
      × hostSusceptibility
      × конфигМножитель

если доза ≥ порогЗаражения(штамм, хост):
     попытка заражения
иначе:
     доза *= 0.97   // организм справляется с малой дозой

порогЗаражения = baseThreshold
               × (1 + hostImmunity)
               × (1 + crossImmunityProtection)
               × (strain.reg/dose_sensitive ? 3.0 : 1.0)
               / affinity(strain, host)
```

### Почему это правильно

- **Костюм имеет смысл.** 90% защиты не «сработал/не сработал», а «ты можешь
  пробыть здесь втрое дольше». Это читаемо и честно.
- **Короткий контакт прощается.** Пробежать через заражённый чанк — нормально.
  Жить в нём — нет. Игрок не умирает от одной ошибки.
- **Есть управляемое напряжение.** HUD показывает накопленную дозу → игрок
  принимает решения («успею ли я ещё раз зайти»). Это и есть геймплей вокруг
  опасности.
- **`reg/dose_sensitive` становится реальным инструментом биобезопасности.**

### Источники экспозиции

| Источник | Величина (базовая, в единицах дозы/сек) |
|----------|------------------------------------------|
| Загрязнение чанка, концентрация C | `C / 255 × 1.0` |
| Рядом заражённый хост в острой стадии | `0.5 × shedding × 1/dist²` |
| Открытый образец/культура в руках | `3.0` |
| Съеденная заражённая еда | `8.0` единоразово |
| Выпита заражённая вода | `6.0` единоразово |
| Укус/урон от заражённого моба (bloodborne) | `10.0` единоразово |
| Укус переносчика (vector) | `12.0` единоразово |
| Разбитая пробирка / авария | `25.0` единоразово |
| Снятие незадезактивированного костюма | `15.0` единоразово |

## 4. Стадии болезни

```
НЕТ ЗАРАЖЕНИЯ
   ↓ доза превысила порог
ИНКУБАЦИЯ (incubating)
   • симптомов нет
   • вирусная нагрузка растёт
   • передача: только если есть evasion/asymptomatic_shedding или transmission с инкубации
   • игрок НЕ знает, что заражён, пока не сделает анализ крови
   ↓ нагрузка > порога симптомов
ПРОДРОМ (prodromal)
   • слабые симптомы, первый намёк (кашель, лёгкая слабость)
   • передача частичная
   • ЗДЕСЬ окно для дешёвого лечения — это важно для баланса
   ↓
ОСТРАЯ СТАДИЯ (acute)
   • симптомы в полную силу по кривой тяжести
   • максимальная передача
   • иммунитет хоста начинает отвечать (скорость ∝ immunogenicity)
   ↓ развилка
   ├── ВЫЗДОРОВЛЕНИЕ (resolved) → запись в иммунную память
   ├── ХРОНИЧЕСКАЯ/ЛАТЕНТНАЯ (latent) → если evasion/latency: неизлечимо, периодические обострения
   └── ТЕРМИНАЛЬНАЯ (terminal) → если lethality прошла проверку: смерть через N тиков
```

### Развилка исхода

```
при каждой проверке в острой стадии:
  immuneResponse += hostImmunity × immunogenicity × (1 + вакцинныйБонус) × antiviralBonus
  viralLoad      += loadGrowthRate × (1 − immuneResponse)

  если immuneResponse > viralLoad → выздоровление
  если viralLoad > lethalThreshold → проверка на летальность
  если есть evasion/latency и immuneResponse > viralLoad → латентность вместо выздоровления
```

Игрок видит **обе полосы** (вирусная нагрузка и иммунный ответ) в диагностическом
UI. Это превращает болезнь из «чёрного ящика с таймером» в читаемую гонку, на
которую можно влиять лечением. Очень важно для столпа «честность».

### Хронические состояния

Переживают выздоровление и остаются навсегда (до специального лечения T4):

| Состояние | От чего | Эффект |
|-----------|---------|--------|
| `chronic/scarring` | `symptom/necrosis` | −2 макс. здоровья за эпизод |
| `chronic/immunodeficiency` | `evasion/immunosuppression` | Иммунитет −25% навсегда |
| `chronic/neural_damage` | `symptom/seizure`, `paralysis` | Редкие приступы без заражения |
| `chronic/latent_reservoir` | `evasion/latency` | Периодические обострения, вечный переносчик |
| `chronic/beneficial_integration` | полезные симптомы + латентность | **Постоянная способность без нагрузки.** Святой грааль симбионта |

Последняя строка — важный приз. Довести полезный штамм до стабильной
благоприятной интеграции = endgame-достижение.

## 5. Иммунитет

```
ImmuneMemoryEntry
├── antigenicSignature: int[8]
├── strength: float 0..1
├── source: NATURAL | VACCINE_INACTIVATED | VACCINE_ATTENUATED | VACCINE_SUBUNIT | ANTISERUM
├── acquiredTick: long
└── decayRate: float
```

- Естественный иммунитет: сильный (0.85), медленно угасает (месяцы игрового времени)
- Инактивированная вакцина: слабее (0.5), угасает быстрее, нужны бустеры
- Живая ослабленная: почти как естественный (0.8)
- Субъединичная: привязана к **конкретному гену**, а не к подписи → устойчива к дрейфу
- Антисыворотка: очень сильная (0.95), но живёт считанные игровые дни — экстренное средство

Память складывается, но не бесконечно: максимум N записей (конфиг, ~16), при
переполнении вытесняется слабейшая. Это не даёт игроку собрать «иммунитет ко
всему» и сохраняет напряжение.

**У `host/undead` иммунитет = 0 и памяти нет.** Зомби — вечный резервуар. Если
штамм попал в поголовье незадед, он не исчезнет из мира сам никогда. Это
серьёзное и запоминающееся последствие: заразить зомби — значит навсегда.

## 6. Передача: как вирус переходит от хоста к хосту

Два принципиально разных канала:

### Канал А: прямая передача хост → хост

Работает для загруженных сущностей в радиусе. Обрабатывается при проверке
инфекции у **заражённого** хоста (он «излучает»), а не у здорового (их больше).

```
для каждого заражённого хоста (не каждый тик, см. ниже):
   shedding = viralLoad × stageMultiplier × host.sheddingMultiplier
   для каждого вектора v в фенотипе:
       радиус = v.radius × transmission[v]
       для сущностей-кандидатов в радиусе (AABB-запрос):
           если проходит проверку вектора (контакт/капля/кровь/еда…):
               цель.exposure[strain] += shedding × transmission[v] / dist²
```

### Канал Б: через среду

Заражённый хост **сбрасывает вирус в загрязнение чанка**, а загрязнение заражает
всех, кто там находится. Это главный механизм на дистанции и для выгруженных
областей.

```
заражённый хост → contamination[чанк] += shedding × envSurvivalFactor
загрязнение чанка → exposure всем хостам в чанке
загрязнение растекается по соседям (бюджетировано)
```

Преимущество: работает между чанками, выживает при выгрузке, не требует, чтобы
обе сущности были загружены одновременно. Подробно — [05-WORLD-CONTAMINATION.md](05-WORLD-CONTAMINATION.md).

### Специальные векторы

- **`transmission/vector` (переносчики).** Заражённый арthropod переносит вирус,
  сам может не болеть (`can_carry_asymptomatically`). Пчёлы — самые опасные:
  летают далеко, посещают много блоков, возвращаются в улей → улей становится
  очагом. Отличная эмерджентная ловушка для игрока, у которого есть пасека.
- **`transmission/fomite` (предметы).** Предметы получают `DataComponent`
  с загрязнением. Передаётся при взятии в руки, при открытии заражённого
  сундука, при надевании брони. **Игрок сам разносит инфекцию по своей базе** —
  самое коварное и самое интересное.
- **`transmission/vertical`.** При размножении животных детёныш рождается
  заражённым. Штамм закрепляется в поголовье и не вымывается.
- **`transmission/fluid`.** Источники воды, котлы, бутылки получают загрязнение.
  Вода **течёт** → загрязнение идёт по течению вниз. Колодец деревни — ужасающая
  цель.

## 7. Абстрактная симуляция выгруженных областей

Самое важное техническое решение всей системы заражения.

**Проблема:** эпидемия должна развиваться, даже когда игрок в другом конце мира.
Но тикать всё — невозможно.

**Решение: статистическая симуляция по времени отсутствия.**

Каждая область с заражением (деревня, биом-кластер, «очаг») регистрируется в
`OutbreakRegistry` (SavedData уровня) как агрегат:

```
Outbreak
├── center: ChunkPos
├── radius: int
├── strainId: UUID
├── populationEstimate: int          // оценка числа хостов по типам
├── infectedEstimate: Map<HostProfile, int>
├── immuneEstimate: Map<HostProfile, int>
├── deadCount: int
├── lastSimulatedTick: long
└── evolutionState: GenomeDriftState  // накопленный дрейф и мутации
```

Когда игрок приходит обратно (или раз в N тиков для очагов рядом):

1. Считаем `elapsed = now − lastSimulatedTick`
2. Прогоняем **SIR-подобную модель** (восприимчивые → инфицированные →
   выздоровевшие/мёртвые) шагами по игровым дням — это десятки арифметических
   операций, а не тысячи тиков
3. Применяем эволюцию штамма за это время (мутации + отбор по приспособленности)
4. При загрузке чанков **материализуем** результат: нужное число сущностей
   получает `InfectionState`, нужное число помечается мёртвыми/выздоровевшими,
   загрязнение чанков обновляется

Это даёт настоящую эпидемию в масштабе мира при почти нулевой стоимости. И это
то, что отличает нас от всех существующих модов: **эпидемия идёт, пока тебя нет.**

## 8. Бюджет производительности

Жёсткие требования. Нарушение = отклонение на ревью.

| Что | Как часто | Ограничение |
|-----|-----------|-------------|
| Проверка инфекции у сущности | **каждые 20 тиков**, со сдвигом `entityId % 20` | Нагрузка размазана, не бывает пиков |
| Излучение/передача от заражённого | каждые 20 тиков, вместе с проверкой | AABB-запрос только если `shedding > 0` |
| Проверка экспозиции от загрязнения | каждые 20 тиков | Чтение загрязнения чанка — O(1), ленивый распад |
| Растекание загрязнения | каждые 100 тиков | Бюджет: максимум 64 чанка за проход, круговая очередь |
| Трансформация блоков (порча) | каждые 100 тиков | Бюджет: максимум 16 блоков на уровень за проход |
| Симуляция очага | при загрузке + каждые 1200 тиков для близких | Чистая арифметика, O(дней) |
| Пересчёт фенотипа | только при изменении генома | Кэш в объекте штамма |
| Герметичность помещения | каждые 40 тиков + по событию блока | Инкрементально, flood-fill только при изменении |

**Правило:** если механика требует итерации по всем чанкам или всем сущностям
каждый тик — она спроектирована неправильно. Всегда: индекс + очередь + бюджет +
ленивое вычисление.

## 9. Что обязательно проверить тестами

- Доза копится и затухает по формуле, порог срабатывает корректно
- Костюм с защитой 0.9 действительно растягивает время до заражения в ~10 раз
- Переход по стадиям идёт в одну сторону, нельзя «перепрыгнуть» стадию
- Выздоровление пишет иммунную память с правильной подписью
- `evasion/latency` всегда приводит к латентности, а не к выздоровлению
- `host/undead` никогда не выздоравливает и никогда не получает память
- Тег `biohazard:immune` полностью исключает сущность из системы
- SIR-симуляция за 10 дней одним шагом даёт результат, близкий к 10 шагам по дню
  (проверка согласованности абстрактной и точной симуляции — критичный тест)
- Сохранение/загрузка мира не теряет состояние инфекции и очагов
- Вертикальная передача работает при размножении, но только с нужным геном
