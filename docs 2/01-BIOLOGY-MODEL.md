# 01 — Модель биологии: геном, гены, фенотип, штаммы

Это ядро мода. Всё остальное — обвязка вокруг этой модели. Если менять что-то
здесь, менять придётся везде.

**Главный принцип:** игрок редактирует **геном** (причина), а играет против
**фенотипа** (следствие). Фенотип всегда вычисляется из генома детерминированно.
Игрок никогда не правит фенотип напрямую.

```
Геном (то, что редактирует игрок)
  ↓ детерминированное вычисление, кэшируется
Фенотип (набор числовых характеристик)
  ↓ поведение в мире
Заражение, симптомы, распространение, загрязнение
```

---

## 1. Структура генома

**Геном — это линейная цепь с позициями, а не набор слотов.** Где стоит ген,
важно не меньше, чем какой это ген: позиция определяет экспрессию, конфликты
действуют только между близко стоящими генами, а в хрупких зонах гены мутируют
втрое чаще.

Полное описание этой головоломки и операций над цепью — в
**[01B-GENOME-ENGINEERING.md](01B-GENOME-ENGINEERING.md)**. Здесь — только
структура данных и биологические величины.

```
Genome
├── chassis: ResourceKey<Gene>      // структурный ген. Задаёт РАСКЛАДКУ цепи:
│                                   // промоторы, хрупкие зоны, терминальные области
├── length: int                     // ёмкость в позициях (8 на T1 … 26 на T4)
├── layout: GenePlacement[]         // что стоит и НА КАКОЙ позиции
└── lineage: GenomeLineage          // откуда взялся (для Кодекса)

GenePlacement
├── gene: ResourceKey<Gene>         // объект реестра (датапак)
├── position: int                   // начальная позиция в цепи
├── mutationLoad: int               // накопленные мутации в этом гене
└── locked: boolean                 // закреплён (не мутирует, но дорого)

// Экспрессия НЕ хранится — она ВЫЧИСЛЯЕТСЯ из позиции и раскладки промоторов.
// Игрок не крутит ползунок: он переставляет ген ближе или дальше от промотора.
```

### Почему именно так

Рассматривались альтернативы:

| Вариант | Почему отклонён |
|---------|-----------------|
| Непрерывный вектор характеристик (заразность 0–100, летальность 0–100…) | Нет открытия, нет эмерджентности. Игрок сразу видит всё. Это ползунки, а не биология |
| Настоящая последовательность «нуклеотидов» (строка) | Непрозрачно, игрок не может строить планы, UX ужасен |
| Фиксированные локусы с аллелями (как пчёлы Forestry) | Слишком жёстко: нельзя добавить новую категорию гена аддоном, не сломав формат |
| Слоты + гены из реестра + ползунок экспрессии | **Отклонено по прямому требованию заказчика: это «выбор клеточек».** Нет пространственной головоломки, нет причины думать |
| **Линейная цепь с позициями, промоторами и хрупкими зонами** ✅ | Головоломка укладки (ограниченная длина, размеры генов, конфликты по соседству, промоторы), открытие (правила неизвестны), расширяемость (аддон регистрирует ген), прогрессия (контроль над позицией растёт с тиром) |

**[решение автора документа]** Выбран последний вариант. Ключевое следствие:
ёмкость ограничена, гены занимают разную длину, конфликтующие гены приходится
разносить спейсерами, а хорошие промоторы — дефицит. Игрок всегда решает задачу
укладки, а не заполняет форму.

## 2. Два ограничителя: ёмкость и стабильность

Это главный балансирующий механизм мода. Без него игрок соберёт «бога» на
третьем часу.

### Ёмкость генома (длина цепи)

Каждый ген занимает `size` подряд идущих позиций (1–6). Сумма занятых позиций,
включая спейсеры и шрамы, не может превышать длину цепи. Длина определяется
**оборудованием**, на котором собран геном:

| Тир | Оборудование | Длина цепи | Контроль позиции |
|-----|--------------|-----------|------------------|
| T1 | Культуральный бокс | 8 | нет (только удаление генов) |
| T2 | Генетический сплайсер | 13 | **нет** — вставка в случайную позицию |
| T3 | Синтезатор генома | 19 | **да** — направленная вставка и перемещение |
| T4 | Комплекс de novo синтеза | 26 | **полный** — вся цепь по чертежу |

Строка «контроль позиции» — это и есть главная ось прогрессии мода. Подробно —
[01B-GENOME-ENGINEERING.md](01B-GENOME-ENGINEERING.md), раздел 2.

Перегруза как такового нет: в цепь физически не влезет больше, чем её длина.
Зато есть **шрамы** от делеций — мёртвые позиции, которые занимают место, пока
их не отремонтируют (T3).

### Стабильность генома (Genomic Stability), 0–100

```
stability = 100
          − Σ(gene.instability × expression/100)      // врождённая нестабильность генов
          − adjacencyConflictPenalty                  // конфликты ТОЛЬКО между близкими генами
          + adjacencySynergyBonus                     // синергии ТОЛЬКО между близкими генами
          − mutationLoad × 1.5                        // накопленные мутации
          − scarCount × 2                             // шрамы от делеций
          − occupiedPositions × 0.8                   // длинная плотная цепь хрупче
          − overlapCount × 15                         // перекрытия генов (T4)
          + stabilizerBonus                           // реагенты, high_fidelity, криохранение
```

Обрати внимание: `adjacencyConflictPenalty` зависит от **раскладки**, а не только
от состава. Те же два гена могут не конфликтовать вовсе, если развести их
спейсерами. Это превращает стабильность из пассивного числа в задачу, которую
игрок активно решает.

**Пороги:**

| Стабильность | Поведение |
|--------------|-----------|
| 80–100 | Штамм стабилен. Мутации только по своему `mutationRate`. |
| 55–79 | Лёгкий дрейф. Экспрессия генов колеблется ±5 при репликации. |
| 35–54 | **Нестабилен.** Шанс потерять случайный ген при каждой репликации. В UI жёлтое предупреждение. |
| 15–34 | **Критически нестабилен.** Быстрая деградация, спонтанные мутации, культура может погибнуть. |
| 0–14 | Нежизнеспособен. Культура гибнет за 1–2 цикла. Образец теряется. |

Стабильность — это **естественный верхний предел силы штамма**. Хочешь восемь
мощных генов — получи штамм, который развалится через два дня. Хочешь
надёжный — упрись в ёмкость.

### Конфликты генов

Матрица конфликтов задаётся **датапаком**, не кодом. Четыре уровня.

**Два правила, без которых конфликты не работают как задумано:**

1. **Конфликт и синергия действуют только в пределах радиуса интерференции**
   (по умолчанию 2 позиции). Разнёс гены — конфликта нет, но потратил ёмкость на
   спейсеры. Это ядро головоломки укладки.
2. **Игрок изначально не знает матрицу.** Конфликты открываются экспериментально
   (собрал геном с этими генами рядом → измерил стабильность → правило записалось
   в Кодекс). Таблица ниже — для разработчика, не для игрока.

| Уровень | Штраф стабильности | Эффект |
|---------|-------------------|--------|
| `synergy` | **+8** | Бонус: гены усиливают друг друга |
| `minor` | −10 | Терпимо |
| `major` | −25 | Серьёзно, нужна компенсация |
| `lethal` | — | Штамм не собирается вообще, сплайсер отказывает |

Примеры (полная таблица — в датапаке `biohazard:gene_interactions`):

| Пара | Уровень | Биологическое обоснование |
|------|---------|---------------------------|
| `env/sporulation` × `structure/enveloped` | `lethal` | Оболочка не выдерживает спорообразования |
| `transmission/aerosol` × `structure/enveloped` | `major` | Оболочечные вирусы плохо переносят высыхание в аэрозоле |
| `transmission/aerosol` × `env/desiccation` | `synergy` | Устойчивость к высыханию — то, что нужно аэрозолю |
| `replication/rapid` × `evasion/mimicry` | `major` | Много антигена → мимикрия не спасает |
| `replication/rapid` × `replication/high_fidelity` | `major` | Скорость против точности |
| `tropism/plant` × `tropism/mammal` | `lethal` (до T4) | Межцарственный барьер. Снимается геном `structure/chimeric_shell` |
| `symptom/hemorrhage` × `transmission/aerosol` | `minor` + природный тредофф | Хост слишком быстро умирает |
| `evasion/latency` × `replication/slow_persistent` | `synergy` | Классическая стратегия персистенции |
| `reg/kill_switch` × любой `evasion/*` | `minor` | Уклонение мешает работе предохранителя |

## 3. Категории генов

Все гены — объекты датапак-реестра `biohazard:gene`. Аддон добавляет ген JSON-файлом.
Поведение берётся из `GeneType` (код), конкретика — из JSON.

### 3.1 STRUCTURE — тип вириона (ровно 1, обязателен)

| Ген | size | Эффект |
|-----|------|--------|
| `structure/naked_capsid` | 2 | Базовый. +50% выживаемость вне хоста, −20% заразность. Устойчив к спиртовой дезинфекции. |
| `structure/enveloped` | 3 | +35% заразность, +уклонение от иммунитета, −60% выживаемость вне хоста. Убивается мылом/спиртом (дешёвая дезактивация). |
| `structure/spore_coat` | 4 | Огромная выживаемость вне хоста (месяцы), очень медленное заражение, требует высокой дозы. |
| `structure/chimeric_shell` | 6 | **T4.** Снимает межцарственные конфликты тропизма. Очень дорогой, −15 стабильности. |

### 3.2 TROPISM — к кому вирус может прикрепиться (минимум 1)

Тропизм работает через **рецепторы**: у каждого профиля хоста есть набор
рецепторов, ген тропизма кодирует связывание с одним из них. Подробно — в
[02-INFECTION-MODEL.md](02-INFECTION-MODEL.md).

| Ген | size | Рецептор | Кого затрагивает |
|-----|------|----------|------------------|
| `tropism/mammalian` | 2 | `receptor/ace_like` | Корова, свинья, овца, лошадь, кролик, волк, лиса, кот, лама |
| `tropism/primate` | 4 | `receptor/ace_like_primate` | **Игрок, житель, зомби-житель.** Дорогой — это «опасный» ген |
| `tropism/avian` | 2 | `receptor/sialic_avian` | Курица, попугай, пчела? нет — птицы |
| `tropism/aquatic` | 2 | `receptor/gill_epithelium` | Рыбы, аксолотль, черепаха, дельфин |
| `tropism/arthropod` | 2 | `receptor/chitin_gut` | Паук, пчела, серебрянка, чешуйница. **Открывает путь к векторной передаче** |
| `tropism/undead` | 3 | `receptor/necrotic_tissue` | Зомби, скелет, утопленник, иссушитель-скелет. Особое: у мёртвой ткани нет иммунитета |
| `tropism/plant` | 2 | `receptor/cellulose` | Посевы, листва, трава, деревья |
| `tropism/fungal` | 3 | `receptor/chitin_wall` | Грибы, мицелий, грибной блок, незер-грибы |
| `tropism/nether_fauna` | 4 | `receptor/thermal_endotherm` | **T3.** Хоглин, свинолюд, страйдер. Требует `env/thermostable` |

**Межвидовой барьер:** `expression` гена тропизма определяет, насколько хорошо
вирус садится на этот рецептор. Низкая экспрессия = вирус почти не заражает.
Поднять экспрессию можно двумя способами: генной инженерией (дорого, нужен T3)
или **серийным пассажем через нужного хоста** (дёшево, долго, опасно —
см. [03-EVOLUTION.md](03-EVOLUTION.md)).

### 3.3 TRANSMISSION — как передаётся (минимум 1)

| Ген | size | Радиус / условие | Примечание |
|-----|------|------------------|------------|
| `transmission/contact` | 1 | 2 блока | Базовый, дешёвый |
| `transmission/droplet` | 2 | 5 блоков | **Требует** `symptom/cough` или `symptom/sneeze` для полной эффективности |
| `transmission/aerosol` | 4 | 14 блоков, проходит по вентиляции и через чанки | Самый опасный. Нужна env-стабильность |
| `transmission/fluid` | 2 | Заражает источники воды, котлы, бутылки | Вода разносит по течению |
| `transmission/bloodborne` | 2 | Только при нанесении/получении урона | Низкий R, но обходит костюм без защиты рук |
| `transmission/vector` | 3 | Требует рядом арthropod-хоста | Переносчик летит далеко. Пчёлы — страшный переносчик |
| `transmission/foodborne` | 2 | Через еду и питьё | Работает на дистанции в сундуках |
| `transmission/soilborne` | 2 | Через землю/посевы, персистирует в блоке | Медленно, но очень устойчиво |
| `transmission/fomite` | 3 | Через предметы: инструменты, броня, содержимое сундуков | Коварно — игрок разносит сам |
| `transmission/vertical` | 1 | Потомству при размножении животных | Закрепляется в поголовье навсегда |

### 3.4 REPLICATION — скорость и точность

| Ген | size | Эффект |
|-----|------|--------|
| `replication/rapid` | 2 | Инкубация ×0.5, вирусная нагрузка растёт ×2, **иммуногенность +40%** (иммунитет быстро реагирует) |
| `replication/slow_persistent` | 2 | Инкубация ×2.5, нагрузка растёт медленно, иммуногенность −30% |
| `replication/error_prone` | 1 | Частота мутаций ×3, стабильность −12. **Ключевой инструмент направленной эволюции** |
| `replication/high_fidelity` | 4 | Частота мутаций ×0.25, стабильность +15 |
| `replication/segmented` | 3 | Геном делится на сегменты → возможна **реассортация** при ко-инфекции. Стабильность −10 |

### 3.5 EVASION — уклонение от иммунитета

| Ген | size | Эффект |
|-----|------|--------|
| `evasion/antigenic_drift` | 3 | Антигенная подпись смещается со временем → **вакцины перестают работать**. См. раздел 6 |
| `evasion/latency` | 4 | Вирус интегрируется и уходит в латентность. **Штамм нельзя излечить полностью** — только подавить. Периодические обострения |
| `evasion/immunosuppression` | 3 | Иммунитет хоста −40%. Открывает путь ко-инфекциям другими штаммами |
| `evasion/mimicry` | 5 | Иммунитет почти не распознаёт. Очень сильно, очень дорого |
| `evasion/asymptomatic_shedding` | 2 | Симптомы слабые/поздние, но передача полная. Хост не знает, что болен |

### 3.7 SYMPTOM — полезная нагрузка (то, ради чего всё)

Самая большая категория. Делится на три группы.

**Вредные** (основа боевых штаммов, и то, с чем борется игрок):

| Ген | size | Эффект на хоста |
|-----|------|-----------------|
| `symptom/fever` | 1 | Урон со временем, тряска камеры, −скорость |
| `symptom/cough` | 1 | Звук (привлекает мобов), включает каплю/аэрозоль, короткая остановка действия |
| `symptom/hemorrhage` | 3 | Сильный урон, частицы крови, высокая летальность |
| `symptom/necrosis` | 3 | Макс. здоровье падает, видимая порча тканей, необратимо без лечения |
| `symptom/emaciation` | 2 | Голод тратится ×3 |
| `symptom/paralysis` | 3 | Периодическая обездвиженность (короткая, с телеграфом) |
| `symptom/blindness` | 2 | Туман/слепота приступами |
| `symptom/photosensitivity` | 2 | Урон на солнце |
| `symptom/insomnia` | 1 | Нельзя спать, растёт «усталость» → дебаффы |
| `symptom/neuro_aggression` | 3 | **Мобы:** агрессивны ко всем. **Игрок:** нет прямого эффекта, только косметика |

| `symptom/thermal_tolerance` | 3 | Защита от огня и холода | Уязвимость к воде/урону от зелий |
| `symptom/toxin_resistance` | 2 | Иммунитет к яду и отравлению | — |
| `symptom/pheromone_signaling` | 3 | Заражённые мобы того же штамма не атакуют | Чистые мобы агрессивны к тебе |

**Критично для баланса:** все полезные симптомы требуют **активной вирусной
нагрузки**. Как только игрок лечится — способность уходит. То есть сила = быть
заражённым = быть переносчиком и риск мутации. Это и есть цена.

### 3.8 REGULATORY — управление и биобезопасность

Эти гены **ослабляют** штамм, и это их смысл. Они — инструменты игрока против
собственного творения.

| Ген | size | Эффект |
|-----|------|--------|
| `reg/incubation_extended` | 1 | Долгая инкубация (дольше скрытая передача) |
| `reg/dose_sensitive` | 1 | Нужна высокая доза → случайный контакт не заражает |
| `reg/self_limiting` | 2 | Штамм самоугасает через N игровых дней. **Предохранитель** |
| `reg/host_restriction` | 2 | Жёстко один вид хоста, тропизм за его пределы не работает |
| `reg/kill_switch` | 3 | **T3.** Вирус гибнет без периодической дозы внешнего вещества-индуктора. Делает штамм «ручным» |
| `reg/temperature_gated` | 2 | Активен только в заданном диапазоне температуры биома |
| `reg/attenuated` | 2 | Все вредные симптомы ×0.3. Основа живых ослабленных вакцин |

## 4. Фенотип: что вычисляется из генома

Фенотип — **кэшируемая** структура, пересчитывается только при изменении генома.
Чистые функции без зависимостей от Minecraft → покрываются юнит-тестами.

```
Phenotype
├── hostAffinity: Map<ResourceKey<HostProfile>, float>   // 0..1 по каждому виду
├── transmission: Map<ResourceKey<Vector>, float>        // сила по каждому пути
├── incubationTicks: int
├── loadGrowthRate: float            // как быстро растёт вирусная нагрузка
├── virulence: float                 // тяжесть симптомов
├── lethality: float                 // шанс смерти в терминальной стадии
├── immunogenicity: float            // как легко иммунитет его находит
├── envHalfLifeTicks: int            // период полураспада вне хоста
├── mutationRate: float
├── antigenicSignature: int[8]       // вектор для кросс-иммунитета, см. раздел 6
├── hazardClass: HazardClass         // I..V, вычисляется, показывается игроку
├── symptoms: List<SymptomEntry>     // с кривыми тяжести по стадиям
└── stability: int
```

### Базовые формулы (все коэффициенты — конфиг)

```
// Сила передачи по конкретному пути
transmission[v] = vectorGene.base
                × (expression / 100)
                × envSurvivalFactor(v)          // аэрозоль зависит от env-генов
                × symptomSupport(v)             // droplet без cough = ×0.4
                × structureModifier(v)

// Заразность конкретного хоста
infectivity(host) = Σ_v transmission[v]
                  × hostAffinity[host]
                  × (1 − hostImmunity(host))

// Главный тредофф летальность↔распространение — ЕСТЕСТВЕННЫЙ, не искусственный:
// хост с высокой virulence быстро умирает → меньше тиков на передачу.
// Мы НЕ ставим искусственный штраф. Это выходит само из симуляции.

expectedTransmissions ≈ infectivity × daysAlive(virulence)
```

**Важное дизайнерское следствие:** мы не прописываем правило «летальность снижает
распространение». Мы просто симулируем смерть хоста, и правило возникает само.
Игрок может это измерить приборами и вывести закономерность — вот это и есть
«глубокая, основанная на реальной биологии система».

### Класс опасности (Hazard Class)

Вычисляется из фенотипа, показывается игроку **крупно и всегда**. Определяет
требуемый уровень BSL для работы со штаммом (см. [07-CONTAINMENT.md](07-CONTAINMENT.md)).

| Класс | Условие (упрощённо) | Требуемый BSL |
|-------|---------------------|---------------|
| **I** — безвредный | Нет вредных симптомов, нет тропизма к примату | BSL-1 |
| **II** — умеренный | Лёгкие симптомы ИЛИ тропизм к животным с передачей | BSL-2 |
| **III** — опасный | Тропизм к примату ИЛИ летальность > 0.2 ИЛИ аэрозоль | BSL-3 |
| **IV** — критический | Тропизм к примату + аэрозоль + летальность > 0.4 | BSL-4 |
| **V** — экзистенциальный | Класс IV + (`evasion/latency` ИЛИ межцарственный тропизм) | BSL-4 + особый протокол |

## 5. Штамм (Strain): идентичность и родословная

**Геном** — это рецепт. **Штамм** — конкретный зафиксированный экземпляр с
историей.

```
Strain
├── id: UUID
├── genome: Genome                  // снимок, неизменяемый
├── designation: String             // автогенерируемое научное имя
├── customName: String?             // игрок может переименовать
├── parentIds: List<UUID>           // 1 = мутация, 2 = рекомбинация, 0 = природный
├── discoveredTick: long
├── discoveredBy: UUID?             // игрок
├── origin: StrainOrigin            // NATURAL | ENGINEERED | MUTATED | RECOMBINED | PASSAGED
├── knownGenes: Set<ResourceKey>    // что игрок уже отсеквенировал (знание ≠ факт)
└── stats: StrainStats              // сколько заразил, где встречался, сколько убил
```

### Имена штаммов

Автогенерация в научном стиле, узнаваемая и сортируемая:

```
PBH-7 «Крапива» var. B.2.1
│     │          └── вариант: ветка родословной
│     └── имя семейства: из таблицы датапака, одно на корневой штамм
└── номер семейства по порядку открытия в мире
```

Мутировавший потомок наследует семейство и получает следующий вариант:
`B.2.1` → `B.2.1.1`. Рекомбинант получает новую ветку с отметкой обоих
родителей. Это даёт читаемую историю эпидемии в Кодексе.

### Реестр штаммов мира

Штаммы создаются **в игре**, поэтому это не реестр и не датапак, а `SavedData`
уровня: `StrainManager`. Хранит все штаммы, когда-либо существовавшие в мире,
и дерево родословной. Предметы ссылаются на штамм по UUID через `DataComponent`.

Подробности хранения и синхронизации — в [10-ARCHITECTURE.md](10-ARCHITECTURE.md).

### Знание против факта

**Ключевая механика честной непрозрачности.** Геном штамма существует на сервере
полностью. Клиент получает только то, что игрок **узнал**:

- Не исследованный образец: `Неизвестный патоген`, виден только класс опасности (по приборам)
- После микроскопии: видны структура и примерное число сегментов
- После секвенирования: видны конкретные гены, по одному за цикл
- Экспрессию и мутационную нагрузку видно только после полного анализа

Это и защита от читов через клиент, и источник того самого удовольствия от
открытия.

## 6. Антигенная подпись и кросс-иммунитет

Это механика, которая делает мод живым на длинной дистанции.

`antigenicSignature` — вектор из 8 целых (0–255), вычисляется из состава генома
(хеш по активным генам + их экспрессии). **Антигенная дистанция** между двумя
штаммами = манхэттенское расстояние между их подписями.

```
Иммунитет хоста к штамму S:
  для каждой записи иммунной памяти M:
     d = antigenicDistance(M.signature, S.signature)
     protection = M.strength × max(0, 1 − d / crossImmunityRange)
  итог = max(protection по всем M)
```

Следствия, которые дают моду стратегическую глубину:

- Переболевший получает защиту от похожих штаммов — **но не от далёких**
- Вакцина защищает в радиусе антигенной дистанции
- Ген `evasion/antigenic_drift` **медленно смещает подпись живого штамма в мире**
  → через несколько недель вакцина перестаёт работать → **нужна ревакцинация и
  новая разработка**
- Вакцина на основе одного консервативного гена (субъединичная, T3) защищает от
  всех штаммов с этим геном независимо от дрейфа → осмысленный стратегический выбор
- Два штамма с далёкими подписями могут сосуществовать в одном хосте → ко-инфекция
  → рекомбинация

Подробно про медицину — [06-MEDICINE.md](06-MEDICINE.md).

## 7. Симбионты: полезные штаммы как endgame

Отдельная важная ветка дизайна, вытекающая из модели.

Игрок может сконструировать штамм, который:
- имеет только полезные симптомы,
- имеет `reg/host_restriction` на примата,
- имеет `reg/self_limiting` или `reg/kill_switch`,
- имеет `replication/high_fidelity` для стабильности,
- и заразить **себя сознательно**.

Результат: постоянная модификация тела. Это настоящий endgame-контент: сборка
«билда» персонажа через биологию, а не через броню.

**Цена, встроенная в модель, без искусственных штрафов:**

1. Полезные симптомы требуют активной вирусной нагрузки → игрок **постоянно
   заражён** → он является переносчиком и может заразить деревню или свои животных
2. Нагрузка требует поддержки: `kill_switch` требует периодической дозы индуктора →
   производственная цепочка «лекарства для себя» на всё прохождение
3. Вирус в игроке **мутирует** по общим правилам. Можно проснуться с
   `symptom/photosensitivity` в придачу. Нужен мониторинг себя и коррекция
4. Иммунная система хоста борется → симбионт постепенно подавляется →
   нужны ревакцинации наоборот (иммуносупрессия)

Это даёт петлю, которая живёт десятки часов и не превращается в «включил
и забыл».

## 8. Природные патогены: откуда берётся первый вирус

**Игрок не создаёт жизнь с нуля.** Он находит её. Это и реалистично, и даёт
причину исследовать мир, и решает проблему «с чего начать».

Природные штаммы генерируются **детерминированно от сида мира**, поэтому в
каждом мире свой набор — это сильно поднимает переигрываемость.

| Источник | Где | Что обычно даёт |
|----------|-----|-----------------|
| Гниль зомби, образцы с зомби | Везде | `tropism/undead`, базовые симптомы |
| Больная живность | Редкий спавн заражённых животных | `tropism/mammalian`, `transmission/contact` |
| Болотный мор | Болота, мангры | `tropism/plant`, `env/aquatic_stable` |
| Спящие споры | Глубокие пещеры, глубинный сланец | `structure/spore_coat`, `env/desiccation` |
| Мицелиальные образцы | Грибные поля, Нижний мир | `tropism/fungal` |
| Древние образцы | Древний город, бастион, портальные руины | Редкие T3-гены, `evasion/*` |
| Термофилы | Нижний мир, базальтовые дельты | `env/thermostable`, `tropism/nether_fauna` |
| Эндовые аномалии | Энд, города Энда | Экзотика T4, `structure/chimeric_shell` |
| Загрязнённые структуры | Новая структура мода: заброшенная лаборатория | Готовые опасные штаммы + схемы |

**Важно:** `tropism/primate` **никогда не встречается в природе**. Этот ген можно
получить только двумя способами: синтезировать на T3 или **вывести серийным
пассажем через примата**. То есть перейти к опасным для игрока штаммам — это
осознанный шаг, за который игрок отвечает сам.

## 9. Что обязательно проверить юнит-тестами

Вся эта модель — чистая математика. Она **не должна** зависеть от классов
Minecraft. Это прямое архитектурное требование.

- Вычисление стабильности на всех граничных значениях
- Матрица конфликтов: `lethal` действительно блокирует сборку
- Перегруз ёмкости считается корректно
- Фенотип детерминирован: один геном → всегда один фенотип
- Антигенная дистанция симметрична, дрейф монотонен
- Класс опасности не может быть понижен добавлением вредного гена
- Мутация с фиксированным сидом воспроизводима
- Геном сериализуется и десериализуется без потерь (round-trip codec)
- Невозможно собрать геном без `structure` и без `tropism`
