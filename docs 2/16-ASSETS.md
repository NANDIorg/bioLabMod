# 16 — Ассеты: текстуры, модели, пайплайн

Решено: **2D-текстуры рисует Codex, сложные 3D-модели делаю я.** Этот документ —
про то, как именно, и про одну важную поправку по инструментам.

Объём: ~60 блоков, ~50 предметов, 8 комплектов брони, слои заражения, GUI,
частицы. Это **сотни ассетов** и потенциально узкое место раньше кода, поэтому
пайплайн проверяется пилотом до того, как в него вложатся.

---

## 1. Важная поправка: Blender здесь не работает

**Формат JSON-моделей Minecraft умеет только прямоугольные параллелепипеды.**
Документация Forge говорит прямо: ванильные JSON-модели могут представлять только
прямоугольные боксы; клин или треугольник в этом формате невыразим, и для более
сложной геометрии нужен другой формат. ✅

Следствия:

- **Произвольная геометрия из Blender не экспортируется в блочную модель.**
  Нет пути «смоделировал меш → получил блок». Это не вопрос плагина, это
  ограничение формата.
- Модели сущностей (`ModelPart`) — тоже кубические.
- **Blockbench** — стандартный инструмент именно потому, что он намеренно
  кубический, «чтобы соответствовать визуальному стилю Minecraft». ✅

### Чем на самом деле делаем модели

| Класс модели | Формат | Инструмент | Кто делает |
|--------------|--------|------------|-----------|
| Простые блоки (куб с текстурами) | ванильный JSON | генерация кодом | я |
| Сложные статичные блоки (машины, приборы, мебель) | ванильный JSON, много элементов | **генерация кодом**, правка в Blockbench при нужде | я |
| Предметы | JSON (обычно плоский спрайт) | генерация кодом | я |
| Броня | слои-текстуры + опционально модель | текстуры — Codex, модель — я | оба |
| Анимированные / с костями (центрифуга, биореактор, дрон, шлюз) | **GeckoLib**, Bedrock-style geo JSON | генерация кодом / Blockbench | я |
| Истинно произвольный меш (если понадобится) | **GeckoMesh** (PolyMesh для GeckoLib) | крайний случай | я |
| Рендеры-превью, концепты, референсы | — | **Blender** | я |

**Ключевой момент:** и ванильные модели, и geo-файлы GeckoLib — это **JSON**.
Значит, я могу писать их напрямую текстом и генерировать скриптами. Для 60 блоков
это быстрее и консистентнее, чем мышкой в GUI, и даёт параметризацию (единый
размер корпуса, единая сетка панелей, единое смещение UV). **Blockbench при этом
остаётся как визуальный редактор для проверки и ручной правки** — он открывает и
сохраняет те же файлы.

### GeckoLib — проверено

- Есть сборки под **NeoForge по всей линейке 1.21** (видел 1.21.5, 1.21.8,
  1.21.10, 1.21.11) ✅
- Blockbench имеет формат «GeckoLib Model» и экспортирует Bedrock geo JSON +
  animation JSON ✅
- GeckoLib 5.4 заявляет соответствие актуальным спекам Bedrock geometry 1.21.0 и
  animation 1.8.0 ✅
- ⚠️ Сборок под 1.21.0–1.21.4 в выдаче не было — **сверить с целевой версией**
- ⚠️ В раннем билде 5.0-alpha1 не работали glowmask и анимированные текстуры.
  Нам glowmask нужен (эмиссивные слои заражения!) — проверить на целевой версии

**[решение автора]** GeckoLib берём как зависимость только там, где реально нужна
анимация или кости. Статику делаем ванильным JSON без зависимостей. Это
уменьшает риск и размер обязательных зависимостей.

## 2. Текстуры: честная оценка риска

**Проблема, которую надо проверить до того, как закладываться.** Генерация
пиксель-арта 16×16 нейросетями — исторически слабое место: результат получается
размытым, непоследовательным по палитре и «почти, но не попиксельно». Для
Minecraft это критично: текстура 16×16 — это 256 пикселей, где каждый виден.

Поэтому пайплайн текстур **разный для разных классов**, а не один на всё:

| Класс текстуры | Чем делать | Почему |
|----------------|-----------|--------|
| **Технические 16×16**: панели, кафель, решётки, корпуса машин, вентиляция | **Генерация скриптом** (Python/PIL): геометрия, шум, палитра | Это геометрические узоры. Скрипт даёт идеальную попиксельную точность, единую палитру и вариации «бесплатно». Нейросеть здесь проигрывает |
| **Органические 16×16**: заражённая трава, наросты, биоплёнка, споры, мицелий | **Codex** (генерация), затем квантование палитры и ресайз nearest-neighbor | Органика прощает неточность, и тут сила генерации |
| **Слои заражения на мобов** (оверлеи с альфой) | **Codex** + ручная доводка | Нужен художественный замысел, форма пятен |
| **Предметы 16×16** | **Codex** для сложных, скрипт для простых (пробирки = форма + цвет жидкости) | Пробирки/картриджи параметризуются: один шаблон × цвет штамма |
| **GUI** (фоны, виджеты, иконки) | **Codex** в большем разрешении + сборка скриптом | GUI не обязан быть 16×16, тут генерация работает лучше |
| **Броня** (слои `layer_1`/`layer_2`) | **Codex** + обязательная ручная доводка | Развёртка брони неинтуитивна, с первого раза не выйдет |
| **Концепт-арт, референсы, промо** | **Codex**, свободное разрешение | Тут генерация сильнее всего |

### Параметризация — главный способ сократить объём

Много ассетов можно **не рисовать**, а собирать:

- **Пробирка с образцом** = один шаблон + цвет штамма из антигенной подписи.
  Один ассет вместо бесконечности (см. [14-UX.md](14-UX.md), цвет штамма)
- **Генные картриджи** = шаблон + цвет категории гена
- **Стадии порчи блока** = базовая текстура + процедурный слой поражения
- **Блоки лаборатории** = общая сетка панелей + разные фронтальные накладки
- **Вакцины/препараты** = шаблон флакона + цвет типа
- **Индикаторы машин** = один атлас состояний на все машины

Это снимает, по грубой оценке, **треть всего объёма текстур**. Делать это надо
сразу, а не после того, как нарисованы 200 отдельных файлов.

## 3. Пилот — первая задача по ассетам

**До любого массового производства** проверяем пайплайн на пяти текстурах,
по одной из каждого класса:

1. Техническая: герметичная панель 16×16 (скриптом)
2. Органическая: заражённая трава 16×16 (Codex)
3. Предмет: пробирка с образцом (шаблон + цвет)
4. Оверлей: слой заражения на корову (Codex + доводка)
5. GUI: фон окна секвенатора

Критерий прохождения: **все пять выглядят так, будто сделаны одним человеком**, и
в игре читаются при 100% масштабе. Если нет — пайплайн правим до того, как
вложились.

Это несколько часов работы, которые защищают от переделки сотен файлов.

## 4. Стиль

| Параметр | Решение |
|----------|---------|
| Разрешение | **16×16**, ванильное. Никакого HD |
| Палитра | Ограниченная, единая. Один файл-палитра на мод, из него берут и скрипты, и доводка |
| Лаборатория | Холодная: белый кафель, нержавейка, бирюзовое стекло, жёлто-чёрная биоопасность |
| Заражение | Цвет задаёт штамм в датапаке. Базовые: болезненно-зелёный, багровый, бледно-жёлтый, фиолетовый |
| Детализация | Чуть технологичнее ваниллы, **без перегруза**. Шум и грязь — минимально: при 16×16 они читаются как мусор |
| Контур | Без жёсткой обводки, как в ванилле |
| Эмиссивность | Отдельные `_e`-текстуры для светящихся частей |

**Правило:** если текстура не читается на расстоянии 3 блоков — она слишком
детальная. Проверять в игре, не в редакторе.

## 5. Структура ресурсов

```
assets/biohazard/
├── textures/
│   ├── block/            технические и органические
│   ├── item/             предметы
│   ├── entity/
│   │   └── infection/    слои заражения (оверлеи с альфой)
│   ├── armor/            layer_1 / layer_2 по комплектам
│   ├── gui/              фоны, виджеты, иконки
│   ├── particle/
│   └── palette.png       ЕДИНАЯ палитра, источник истины
├── models/
│   ├── block/            ванильный JSON (генерируется)
│   └── item/
├── geo/                  GeckoLib geometry (только анимированное)
├── animations/           GeckoLib animations
├── blockstates/
└── lang/
    ├── ru_ru.json
    └── en_us.json
```

**Инструменты пайплайна** (не в ассетах мода, в отдельной папке `tools/`):

```
tools/
├── gen_models.py         генерация ванильных JSON-моделей
├── gen_textures.py       процедурные технические текстуры
├── palette.py            квантование к единой палитре
├── downscale.py          ресайз nearest-neighbor + проверка палитры
├── atlas.py              сборка атласов состояний
└── check_assets.py       линтер: все ли текстуры на месте, в палитре, 16×16
```

`check_assets.py` в CI — обязателен. Он ловит самую частую и самую раздражающую
проблему: отсутствующая текстура замечается только в игре, через недели.

## 6. Как мы работаем вместе

| Шаг | Кто | Что |
|-----|-----|-----|
| 1 | я | Пишу спецификацию ассета: что это, размер, палитра, назначение, референсы |
| 2 | Codex | Генерирует по спецификации |
| 3 | я | Квантую к палитре, ресайзю, проверяю в игре |
| 4 | я | Довожу руками то, что не сошлось |
| 5 | я | Модели JSON — генерирую кодом |
| 6 | я | Blender — только если нужен рендер-превью или референс формы |
| 7 | CI | `check_assets.py` + визуальный лист контрольных рендеров |

**Спецификация ассета** — важный артефакт: без неё генерация даёт разнородный
результат. Формат простой:

```
id: block/containment_panel
размер: 16x16
класс: технический (скрипт)
палитра: steel_cold
описание: гладкая стальная панель, тонкий шов по краю,
          4 заклёпки в углах, лёгкий вертикальный градиент
не делать: грязь, царапины, шум, логотипы
референс: ванильный железный блок по тону
```

## 7. Приоритет производства

Текстуры делаются **под этапы кода**, а не все сразу. Иначе рисуем то, что потом
вырежем.

| Этап кода | Нужны ассеты |
|-----------|--------------|
| Этап 1 (вертикальный срез) | ~15 ассетов: набор образцов, пробирка, микроскоп, инкубатор, 1 слой заражения, 2 иконки симптомов. **Можно заглушками** |
| Этап 2 (головоломка генома) | GUI редактора генома — **самый важный визуальный ассет мода**, здесь не экономить |
| Этап 4 (мир) | Блоки порчи, частицы, все стадии |
| Этап 5 (сдерживание) | Блоки лаборатории, броня, GUI контроллера |
| Этап 7 (T3/T4) | Остальные машины |

**До этапа 2 допустимы заглушки** — цветные квадраты с подписью. Это нормально
и правильно: сначала проверяем, что геймплей интересен, потом одеваем.

## 8. Риски

| Риск | Митигация |
|------|-----------|
| **Пиксель-арт 16×16 от нейросети выйдет непригодным** | Пилот из 5 текстур до вложений. План Б: скриптовая генерация + ручная доводка для органики тоже |
| Разнородный стиль между партиями | Единая палитра как файл + спецификации + линтер |
| Объём ассетов тормозит код | Заглушки до этапа 2, параметризация, приоритет по этапам |
| GeckoLib не поддерживает целевую версию или glowmask | Проверить **до** этапа 5. План Б: свой `BlockEntityRenderer` на `ModelPart` |
| Текстура потерялась, замечено поздно | `check_assets.py` в CI |
| Развёртка брони не сойдётся | Это известно сложное место: делать раньше, чем понадобится, с запасом времени |
