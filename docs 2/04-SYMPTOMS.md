# 04 — Симптомы: поведение и внешность

Требование заказчика: вирусы должны **модифицировать поведение и внешний вид**
игрока, животных и NPC, а не просто накладывать баффы/дебаффы. Этот документ — про то,
как это сделать так, чтобы было выразительно и не бесило.

---

## 1. Архитектура симптома

Симптом — не `MobEffect`. Это отдельная сущность с четырьмя независимыми слоями:

```
SymptomType (код)                 — логика поведения, один класс на механику
   ↓ параметризуется
Symptom (объект датапак-реестра)  — конкретный симптом с числами и ссылками
   ↓ применяется с
severity: float 0..1              — вычисляется из стадии × virulence × expression
   ↓ проявляется в
┌─────────────┬──────────────┬────────────────┬──────────────┐
│ МЕХАНИКА    │ ПОВЕДЕНИЕ    │ ВНЕШНОСТЬ      │ ОЩУЩЕНИЕ     │
│ атрибуты,   │ AI-цели      │ слои рендера,  │ экран, звук, │
│ урон, голод │ мобов        │ модель, частицы│ тряска, пост │
└─────────────┴──────────────┴────────────────┴──────────────┘
```

Любой симптом может задействовать любой набор слоёв. Один `SymptomType` в коде
может порождать десятки симптомов в датапаке — **это то, что делает аддоны
реальными без Java**.

### Кривая тяжести

У каждого симптома в датапаке своя кривая по стадиям:

```json
{
  "severity_curve": {
    "incubating": 0.0,
    "prodromal":  0.25,
    "acute":      1.0,
    "latent":     0.1,
    "terminal":   1.0,
    "chronic":    0.4
  },
  "onset_ticks": 200,
  "pulsed": { "interval_ticks": 600, "duration_ticks": 100 }
}
```

`pulsed` — важная вещь: симптом может быть **приступообразным**, а не постоянным.
Приступы гораздо выразительнее и гораздо менее раздражающи, чем постоянный
дебафф.

## 2. Симптомы игрока

### Правила, которые нельзя нарушать

Это самая опасная зона дизайна: легко сделать невыносимо. Жёсткие правила:

1. **Никогда не отбирать управление надолго.** Максимум ~20 тиков (1 сек) за
   приступ, и только с телеграфом.
2. **Всегда телеграфировать.** Перед приступом — звук, вспышка, дрожь. Игрок
   должен успеть отойти от лавы.
3. **Никогда не инвертировать управление.** Это классическая ошибка: ощущается
   как баг, а не как болезнь. Вместо этого — дрейф камеры, дрожь, замедление.
4. **Косметика может быть сильной, механика — нет.** Выглядеть жутко можно на
   100%. Мешать играть — осторожно.
5. **Всё отключаемо в конфиге по категориям.** Тряска камеры и постэффекты —
   отдельные тумблеры (доступность, укачивание).
6. **Фатальный исход только в терминальной стадии**, до которой есть две стадии
   предупреждений и окно лечения.

### Механические проявления

Через `AttributeModifier` с UUID симптома (чистое снятие при лечении):

| Симптом | Атрибуты и эффекты |
|---------|--------------------|
| `fever` | −15% скорость, урон 0.5 HP каждые 5 сек, +тряска |
| `emaciation` | Голод ×3, −10% скорость при сытости < 6 |
| `necrosis` | Макс. здоровье −1 за игровой день болезни (накапливается в хроническое) |
| `hemorrhage` | Урон 1 HP/3 сек, частицы крови, кровавый след на земле |
| `organ_failure` | Таймер до смерти (конфиг, ~3 игровых дня), регенерация отключена |
| `photosensitivity` | 1 HP/2 сек под открытым небом днём |
| `insomnia` | Нельзя спать; растёт счётчик «истощения» → каскад дебаффов |
| `paralysis` | **Приступами:** 15 тиков обездвиженности, за 40 тиков до — громкий звук и дрожь |
| `blindness` | Приступами: сужение обзора + туман на 3 сек |
| `toxin_resistance` | Иммунитет к ядам (полезный) |
| `keratinization` | +4 броня, −12% скорость |

### Поведенческие проявления (мягкое принуждение)

Нельзя заставить игрока что-то делать, но можно создать потребность:

| Симптом | Как ощущается |
|---------|---------------|
| `cough` | **Непроизвольно:** громкий звук (слышат мобы, агрятся), прерывание использования предмета/еды. Это и симптом, и вектор — очень удачная двойная роль |
| `craving` (новый) | Нужно периодически есть конкретный предмет (сырое мясо, гниль, сахар), иначе растущий дебафф. Создаёт зависимость и производственную цепочку |
| `hydrophobia` (новый) | Урон при контакте с водой. Меняет маршруты и постройки |
| `photophobia` | Хочется строить под землёй. Меняет базу |
| `pheromone_signaling` | Заражённые мобы дружественны, чистые — агрессивны. Полностью меняет перемещение по миру |
| `insomnia` | Ночь становится проблемой, нужны альтернативы сну |

**`craving` и `hydrophobia` — лучшие примеры «изменения поведения» без отбора
контроля:** игрок сам меняет то, как играет, потому что мир стал другим.

### Внешность игрока

Технически: дополнительные `RenderLayer` на `PlayerRenderer` + модификация модели.

| Слой | Как реализуется | Применение |
|------|-----------------|------------|
| Наложение текстуры кожи | Доп. слой с альфой поверх скина, цвет из датапака | Бледность, вены, пятна, пигментация, некроз |
| Эмиссивный слой | Слой с собственной яркостью | Биолюминесценция, свечение глаз |
| Геометрические наросты | Доп. кубы, прикреплённые к частям модели | Наросты, кератиновые пластины, грибные тела |
| Деформация модели | Масштаб/поворот частей модели в рендере | Гигантизм, сутулость, искривление |
| Частицы от сущности | Эмиттер на позиции хоста | Спора, пар, капли, мухи |
| Замена модели (T4/крайние случаи) | Полностью другая модель | Крайние трансформации |

**Важно:** игрок должен **видеть себя**. Нужен обязательный просмотр модели в
диагностическом UI и в Кодексе («что со мной происходит»), иначе вся визуальная
работа пропадает в виде от первого лица.

Биолюминесценция делает игрока **настоящим источником света** (dynamic light,
или через `LightLayer`-хак / совместимость с Embeddium/Sodium — проверить) —
это должно быть полезно и заметно.

### Ощущение (постобработка и звук)

| Симптом | Эффект |
|---------|--------|
`fever` | Пульсация экрана в такт «сердцебиению», тёплый оттенок, звук пульса
`hemorrhage` | Красные пятна по краям экрана, нарастающие
`blindness` | Сужение FOV, туман
`seizure` | Короткая дрожь + хроматическая аберрация (с телеграфом)
`neuro_*` | Искажённый, замедленный эмбиент
`photosynthesis` | Тёплое мягкое свечение по краям на солнце (приятный, положительный фидбек)

Все постэффекты — через core shaders с мягкой деградацией, если шейдеры
недоступны, и **с отдельным тумблером в конфиге клиента**.

## 3. Симптомы мобов

Здесь свободы больше: мобами можно управлять полностью.

### Поведение: инъекция AI-целей

При входе в острую стадию симптом добавляет/удаляет `Goal` у моба и снимает при
излечении.

| Симптом | Поведение моба |
|---------|----------------|
| `neuro_aggression` | Удаляется цель «убегать», добавляется «атаковать всё живое». Мирная корова становится угрозой. Очень сильный момент |
| `vector_seeking` (новый) | **Моб ищет других здоровых мобов и идёт к ним.** Вирус заставляет хоста себя распространять. Биологически реально (бешенство) и геймплейно страшно |
| `herd_dispersal` (новый) | Моб уходит от стада далеко → разносит заражение на дистанцию |
| `phototaxis` / `photophobia` | Моб идёт к свету / прячется в темноту. Заражённая живность начинает собираться у факелов базы — отличный жуткий визуал |
| `lethargy` | Моб почти не двигается, не убегает. Лёгкая добыча — ловушка для игрока, который соберёт заражённое мясо |
| `aquatic_seeking` | Моб идёт к воде и заражает водоём |
| `nest_return` | Переносчик возвращается в улей/гнездо → очаг |
| `cognitive_decline` | Моб теряет привязку к дому/работе |

`vector_seeking` — по-моему лучшая механика в этом списке. Она делает вирус
активным агентом с собственным поведением.

### Внешность мобов

| Способ | Применение |
|--------|------------|
| Слой-наложение на текстуру | Основной способ: пятна, вены, бледность, язвы. Один слой на все виды мобов |
| Эмиссивный слой | Свечение |
| Доп. геометрия | Наросты, поросль |
| Деформация | Худоба (сжатие по осям), вздутие |
| Частицы | Споры, муха, пар, капли |
| Цветовой фильтр | Общее обесцвечивание при истощении |

Реализация: **один универсальный `InfectionRenderLayer`**, регистрируемый на все
`LivingEntityRenderer` через событие NeoForge. Текстуры наложения и правила
берутся из датапака симптома. Это значит, что заражённые мобы из чужих модов
тоже будут выглядеть заражёнными — **автоматически, без кода совместимости**.
Очень ценное свойство.

## 4. Жители и деревни: эпидемия, которая имеет значение

Это то, что превращает вирус из личной проблемы в событие мира. И это даёт моду
эмоциональный вес.

### Механика деревни как узла эпидемии

Деревня регистрируется как `Outbreak` с населением. Внутри:

| Стадия деревни | Что видно |
|----------------|-----------|
| **Чистая** | Обычная жизнь |
| **Единичные случаи** | 1–3 кашляющих жителя. Остальные нормально. Первый намёк |
| **Вспышка** | 30%+ больны, часть потеряла профессию, торговля дорожает, меньше рабочих у станций |
| **Коллапс** | Больше половины мертвы или недееспособны, железный голем не справляется, появляются зомби-жители от смертей |
| **Мёртвая деревня** | Пустые дома, загрязнённые блоки, вечный резервуар в зомби-жителях |

Последствия, которые игрок почувствует напрямую:
- цены у торговцев растут с тяжестью вспышки,
- профессии теряются → нет нужных сделок,
- деревня перестаёт расти,
- мёртвая деревня = потерянный ресурс навсегда (почти — можно заселить заново).

### Спасение деревни — важный позитивный контент

Игрок может вмешаться: массовая вакцинация (**вакцинный распылитель**,
**медицинский дрон/пост**), раздача лечения, деконтаминация колодца, карантин
(постройка барьера). За это:

- восстановление профессий и цен,
- постоянный бонус к репутации в деревне (скидки),
- большое количество исследований по эпидемиологии,
- запись в Кодексе о спасённой деревне.

**Это обязательно должно быть в моде.** Без позитивной петли мод скатится в
«ломать интересно, починить незачем», а заказчик просил обе стороны.

### Иллагеры

Аутпосты и особняк — отдельные узлы. Заражённые иллагеры разносят инфекцию в
рейдах → заражённый рейд приходит в деревню. Эмерджентная драма, ничего
скриптовать не надо.

## 5. Растения и посевы

Растительные вирусы — реальный и недоиспользованный в модах пласт.

| Эффект | Проявление |
|--------|------------|
| `blight` | Посевы растут медленнее, урожай меньше, текстура с пятнами |
| `mosaic` | Визуальный узор на листве, замедление роста |
| `wilt` | Растение гибнет через N стадий, превращается в мёртвый блок |
| `gigantism` (полезный) | **Урожай ×2**, но растение заражено и распространяет вирус на соседние посевы и на животных, которые это съели |
| `nitrogen_fixation` (полезный) | Блок земли «удобряется» сам, ускоряя соседей |
| `fruiting` (полезный) | Шанс дополнительного урожая |

Полезные растительные штаммы — **самый доступный вход в «позитивную» ветку
мода**: доступно на T2, риск относительно низкий (растительный тропизм не
заражает игрока), выгода понятна (больше еды). Хороший онбординг в идею
«вирус как инструмент».

И одновременно — ловушка: заражённый урожай, съеденный игроком, даёт дозу; а
если штамм мутирует в сторону `receptor/chitin_wall` → `cellulose`-соседей, он
может перейти на другие виды.

## 6. Как не сделать невыносимо: чек-лист для каждого симптома

Перед добавлением симптома в мод ответить:

- [ ] Видно ли это со стороны? (если нет — добавить визуал)
- [ ] Чувствует ли это игрок без открытия UI? (если нет — добавить фидбек)
- [ ] Есть ли телеграф перед резким эффектом?
- [ ] Может ли это убить игрока без предупреждения? (если да — переделать)
- [ ] Можно ли это отключить в конфиге отдельно?
- [ ] Работает ли это на мобах из чужих модов?
- [ ] Есть ли у игрока способ узнать, какой ген это вызвал?
- [ ] Не ощущается ли это как баг игры? (инверсия управления, пропажа предметов — да, ощущается)
- [ ] Приступообразный вариант был бы выразительнее постоянного?

## 7. Что обязательно проверить тестами

- Снятие симптома полностью убирает все `AttributeModifier` (нет накопления бонусов)
- AI-цели корректно добавляются и удаляются, нет утечки целей при повторном заражении
- Кривая тяжести даёт 0 в инкубации для всех симптомов, кроме явно помеченных
- Приступы не накладываются друг на друга
- Хронические состояния сохраняются при смерти и респавне (по конфигу)
- Рендер-слой не падает на мобах без стандартной модели (мобы чужих модов)
- Все клиентские эффекты корректно выключаются конфигом
- Симптом игрока, применённый на сервере, доходит до клиента и наоборот не
  создаётся клиентом самостоятельно
